# ADR 0001: FSharp.Azure.Cosmos.Quotations architecture

## Status

**Accepted**, 2026-10-02. The decisions were confirmed with the maintainer between 2026-09-26 and 2026-09-28 (§2 and §18), and the maintainer decided on 2026-10-02 to keep the design in the documentation as this record. Implementation follows the roadmap of §16, one pull request per step, starting with Phase 0.

## Context

`FSharp.Azure.Cosmos` wraps the Azure Cosmos DB .NET SDK v3 with F# computation expressions for item operations. Querying today means raw SQL strings in a `QueryDefinition` or the SDK LINQ provider through `IQueryable`. F# `query { }` reaches that provider only after `LeafExpressionConverter` lowers quotations to `System.Linq.Expressions`, which loses F# semantics (options, pipelines, records, unions) on the way. The SDK translator itself inlines captured values as literals, gets null versus undefined wrong, rejects record projections, generates invalid SQL for `Take().Skip()`, loses decimal precision, is closed to extension and caches nothing, and its SQL model, parser and translator are internal to the SDK (§1). Two earlier branches of this repository rewrote quotations into LINQ expressions with a global mutable registry; that approach is rejected.

The maintainer's Cosmos DB application will be the first real consumer, so its query shapes are requirements (§21), and the maintainer's earlier F# LINQ layer over Marten supplies a corpus of 489 cases and a list of defects that must not be repeated (§20).

## Decision

A new package family in this repository translates F# quotations into Cosmos DB NoSQL queries. The key decisions:

- **Quotation-only translation.** Native `Microsoft.FSharp.Quotations.Expr` is translated into Cosmos NoSQL SQL text plus `@parameters` and executed through the public `QueryDefinition` / `Container.GetItemQueryIterator<'T>` / `FeedIterator<'T>` pipeline – never through `System.Linq.Expressions`, the SDK LINQ provider or SDK internals reached by reflection (§1, §4).
- **Own SQL AST and validator.** `FSharp.Azure.Cosmos.Sql` holds an AST that mirrors the SDK grammar `sql.g4` and its `SqlObjects`, a validator for the rules the grammar cannot express, a deterministic SDK-compatible printer, the function catalog as data and a hand-written scalar parser; it has no raw-text case and no SDK dependency (§5, §6).
- **One front-end pivot.** A standalone `cosmosQuery { }` builder that mirrors FSharp.Core naming without inheriting `QueryBuilder`, a functional `Query` module, compiled queries and auto-quoted method arguments all lower through one normalizer into one `QueryModel` (§3, §7, §8). Captured values are always parameters, and plans are cached per translator under a structural shape key (§11).
- **Symbolic optional pairs.** `option`, `voption`, `Skippable`, `Nullable` and nullable references translate as a pair of has-value and value expressions, so every composition works the same in predicates, projections, sort keys and group keys; the truth tables are documented and tested, and ordering between optional values has SQL meaning (§9, §20.3, §20.4, §20.5).
- **Pluggable translators without a global registry.** Immutable `Translator` instances are created from options that carry plugins in two tiers (user plugins, built-in packs), with conflicts detected at creation; an attribute route and a programmatic route register translators; geometry goes through an `IGeometryProvider` contract over abstract operations, so the core references no geometry library (§8).
- **System.Text.Json + FSharp.SystemTextJson only.** Every serializer-dependent fact comes from one `IJsonLayout` service read from the real serializer options; Newtonsoft, the SDK default, is not supported and yields a `LayoutRequired` error (§2, §10).
- **net10.0 for every project**, `System.Collections.Immutable` and `System.Collections.Frozen` in the implementation instead of F# collections, and IcedTasks allowed behind a Debug-build probe, which Phase 0 failed in Debug, so library code keeps `task` for now (§2, §4, §16).
- **Struct tuples preferred.** Struct forms are used inside the implementation and documented first; reference forms stay accepted and give byte-equal SQL under the tuple-kind law (§2, §4, §7, §20.11).
- **No C# source generator.** fsc has no generator pipeline; the plan cache, compiled queries and an optional later build tool and analyzer capture the same benefits (§11).
- **Executable spec conformance.** Every emitted query parses under the SDK grammar; printer and parser laws, golden baselines, an interpreter ported from the SDK's test-only offline engine, three-way differential property tests (F# evaluation, interpreter, emulator) through a Hedgehog MSTest adapter, metamorphic oracles and a plugin conformance kit check the semantics. Database tests follow the maintainer's conventions: Slim, Fat and Default generator variants, class-scoped read-only datasets for property tests and a database per write test (§13, §22).

## Consequences

- Queries become pure, container-independent values with parameterised, cacheable SQL text that keeps F# meaning for options, records, unions, tuples and pipelines, and the translator stays open to extension without global state.
- The existing package drops `net8.0`, so the lockstep version becomes a major release (2.0.0); `Microsoft.Azure.Cosmos` moves to 3.62.0, which raises the minimum for every package through central package management (§2, §5).
- Consumers of the Quotations package take FSharp.SystemTextJson and IcedTasks as dependencies, and clients on the SDK default serializer must switch to System.Text.Json to use it (§2, §5).
- Some results deliberately differ from F# evaluation – ordering between optional values, `undefined` from integer division by zero – and are documented and reported through warning codes (§9, §20.3, §20.15).
- The repository gains a C# grammar test project, shared test infrastructure, two generator projects, a Hedgehog MSTest adapter that is also proposed upstream and a nightly Windows-emulator lane, and the function catalog has to follow SDK updates (§5, §13, §16).
- The `IQueryable` helpers of `FSharp.Azure.Cosmos` stay for APIs that require the SDK LINQ provider (§21.5).

## 1. Context

`FSharp.Azure.Cosmos` wraps the Azure Cosmos DB .NET SDK v3 with F# computation expressions for item operations and Debug-safe `FeedIterator` → `IAsyncEnumerable`/TaskSeq helpers. Querying today means raw SQL strings (`QueryDefinition`) or the SDK LINQ provider through `IQueryable` (`src/Cosmos/IterationExtensions.fs:116-131` is the only coupling to `Microsoft.Azure.Cosmos.Linq`). F# `query { }` only reaches that provider after `LeafExpressionConverter` lowers quotations to `System.Linq.Expressions`, losing F# semantics (options, pipelines, records, unions) on the way. Two unmerged branches (`origin/copilot/implement-linq-translation-methods`, `origin/copilot/handle-fsharp-language-constructs-in-linq`) tried exactly that rewriter approach with a global mutable registry; it is rejected here.

The SDK's own translator has well-known limits *(verified in its source and issue tracker)*: it inlines closure values as literals (no parameterisation), gets null vs undefined wrong (`x == null` → `(x = null)` misses undefined, issue #4864), rejects record/constructor projections (#3728), generates invalid `TOP`-in-subquery SQL for `Take().Skip()` (#908), loses decimal precision (#3606), is closed to extension (#5329/#5382) and caches nothing. Its SQL AST (`SqlObjects`), ANTLR parser (`sql.g4`), planner and translator are all `internal` with no third-party `InternalsVisibleTo` – we own our model but may copy (MIT) its grammar, node inventory, printer rules, golden baselines and the test-only offline interpreter.

### Goals

1. Translate **native `Microsoft.FSharp.Quotations.Expr` only** (never `System.Linq.Expressions`, never the SDK LINQ provider) into Cosmos NoSQL SQL text + `@parameters`, executed through the public `QueryDefinition` / `Container.GetItemQueryIterator<'T>` / `FeedIterator<'T>` pipeline and the repo's existing `FeedIterator<'T>.AsAsyncEnumerable`.
2. Cover F# constructs: pipelines (`|>`, `<|`, `||>`, `|||>`, `<||`, `<|||`), composition (`>>`, `<<`), quotation splicing, point-free forms, `option`/`voption`/`Skippable`, records, anonymous records, classes with inheritance, unions, scalar wrappers, struct and reference tuples, `match`, `if`, `let`, `List`/`Array`/`Seq`/`String`/`Option` module functions, comparison/arithmetic/bitwise operators, closures, `[<ReflectedDefinition>]` helpers.
3. Open, DI-free extensibility for operations and types (geospatial through *any* library, vectors, full text, UDFs, custom scalars) with the core referencing no geometry library.
4. Executable spec conformance: every emitted query parses under the SDK grammar; semantic claims are checked by an interpreter, differential/metamorphic property tests and the emulator.
5. Fit repo conventions: F# 10, **net10.0**, CPM, FAKE, MSTest 4, Unquote, Hedgehog (properties through an MSTest adapter project, §5, §22.6), FsToolkit, TaskSeq, `voption`/struct tuples, `task` and IcedTasks CEs (full names, never hand-rolled `ValueTask`/`Task` wrappers), XML docs (`fsdocs --strict`), Fantomas.

### Non-goals

Routing through LINQ; Newtonsoft document layouts (§2); a C# source generator for F# consumers (impossible, see §11); NativeAOT as a shipped feature (SDK is not trim/AOT annotated, issue #4458; FSharp.SystemTextJson is reflection-based); cross-container joins, CTEs, write statements (the language has none); silent client-side projection fallback; binding to SDK internals via reflection at runtime.

## 3. Why not FSharp.Core `query { }` alone – gap table and builder decision

*(verified in fsi)* A builder that inherits `Microsoft.FSharp.Linq.QueryBuilder` keeps every inherited custom operation, may add its own `[<CustomOperation>]` members, and a `Run` member on the derived type hides the base `Run` overloads and receives the whole CE body as `Expr<QuerySource<'T, IQueryable>>`. So the standard syntax *can* be reused. The gaps below are what `QueryBuilder` (verified member list from `FSharp.Core/Query.fsi`) cannot express or expresses wrongly for Cosmos.

Legend: ✓ usable as is · ≈ usable with translator-side semantics · ✗ missing or not expressible in Cosmos SQL.

| Need (Cosmos SQL clause / execution concern) | FSharp.Core `QueryBuilder` | Gap and plan |
|---|---|---|
| `SELECT TOP n` | `take n` only | ≈ `take` alone → `TOP @n`; explicit `top` keyword for readability |
| `OFFSET n LIMIT m` must appear together | `skip`/`take` independent; lone `skip` untranslatable | ≈ `skip` + `take` → `OFFSET @m LIMIT @n`; a lone `skip` → `OFFSET @m LIMIT 2147483647` with warning `CQ1020` (the maintainer's application pages with an optional offset and an optional count) |
| `SELECT VALUE <scalar>` vs object projection | `select` only | ≈ translator emits `SELECT VALUE` always: scalar → `VALUE expr`, record/anonymous record → `VALUE {"k": …}` |
| `DISTINCT` | `distinct` ✓ | ✓ |
| `ORDER BY a ASC, b DESC` | `sortBy`/`thenBy`(+`Descending`) ✓; `*Nullable` variants are `Nullable<'T>`-only | ≈ option/voption keys need undefined/null ordering semantics; `*Nullable` operations irrelevant for F# records |
| `ORDER BY RANK RRF(…)` (hybrid search) | none | ✗ `orderByRank` + `RRF`/`FullTextScore`/`VectorDistance` markers |
| `GROUP BY` + aggregates | `groupBy`/`groupValBy` return `IGrouping` (group *items*); Cosmos returns keys + aggregates only | ✗ dedicated `groupBy key into g` whose continuation may only use `g.Key` and aggregates |
| `JOIN t IN c.tags` (nested-array self join) | nested `for t in c.Tags do` (SelectMany) ✓ | ✓ |
| `join … on`, `groupJoin`, `leftOuterJoin` | present (`IsLikeJoin`, `on`) | ✗ Cosmos has no cross-container joins, no `ON`, no outer joins → not exposed; subquery joins `JOIN (SELECT VALUE …)` need their own operation |
| `EXISTS`/`ARRAY`/scalar subqueries inside `WHERE`/`SELECT` | `exists`/`all`/`contains` are terminal only | ≈ `List.exists`/`Array.contains`/`List.isEmpty` etc. inside predicates → `EXISTS(SELECT VALUE t FROM t IN …)`, `ARRAY_CONTAINS`, `ARRAY_LENGTH` |
| Terminal aggregates | `count`, `sumBy`, `averageBy`, `minBy`, `maxBy` ✓ | ✓ → `SELECT VALUE COUNT/SUM/AVG/MIN/MAX` |
| `head`, `headOrDefault`, `exactlyOne(OrDefault)`, `find` | present, return `'T` or `default` | ≈ `TOP 1`/`TOP 2` + client check; we return `voption` instead of `default` |
| `last`, `lastOrDefault`, `nth`, `skipWhile`, `takeWhile` | present | ✗ not expressible → must be rejected; with a standalone builder they do not exist at all (compile-time rejection) |
| Execution options (partition key, `MaxItemCount`, continuation, consistency, session token, throughput bucket, metrics, `EnableScanInQuery`, `MaxConcurrency`) | none; `query` returns `IQueryable<'T>` | ✗ `withPartitionKey` in the CE; the rest belongs to execution (`QueryRequestOptions`) |
| Result type | `IQueryable<'T>` executed by the SDK LINQ provider | ✗ `Run` returns a pure `CosmosQuery<'T>` value executed by our `Container` extensions |
| Parameterisation of captured values | after LINQ lowering the SDK inlines literals *(verified)* | ✗ translator hoists captured values into `@p` and caches the SQL template |
| Vector, full text, spatial `ST_*`, `IS_DEFINED`/`IS_NULL`, `RegexMatch`, `DocumentId`, UDFs | none | ✗ marker functions (`Cosmos.Functions`, `Cosmos.Geo`) + pluggable translators |
| `option`/`voption`/`Skippable` semantics | only `Nullable<'T>` awareness | ✗ explicit truth table (§9) |
| `into` continuations, several `where` clauses | ✓ | ✓ |
| Compile-once templates | none | ✗ `CosmosQuery.compile` |
| Struct tuples (`select struct (…)`, `let struct`/`match … with struct` destructuring) | FSharp.Core's LINQ lowering throws on `select struct (…)` ("unreachable" in `RewriteTupleType`) and on every `TupleGet` over a struct tuple (`ArgumentException` in `LeafExpressionConverter`); `sortBy`/`groupBy` with a struct key and struct anonymous record projections work *(verified in fsi, FSharp.Core 10.1.401)* | ✗ both tuple kinds translate, to the same SQL under the tuple-kind law of §7; `LeafExpressionConverter` is never used (§20.11) |

**Decision: a standalone `CosmosQueryBuilder` that mirrors FSharp.Core's naming and attributes (`Quote`/`Run`, `[<ProjectionParameter>]`, `MaintainsVariableSpace`, `AllowIntoPattern`), not a subclass.** Rationale: (a) the non-translatable inherited operations (`last`, `nth`, `skipWhile`, `takeWhile`, `join … on`, `groupJoin`, `leftOuterJoin`, `*Nullable`) then fail at compile time instead of at translation time; (b) return types can be F#-idiomatic (`headOrDefault : 'T voption`, `groupBy` yielding key + aggregate scope) instead of `IGrouping`/`default`; (c) `QuerySource<'T>` becomes a phantom type with no `IQueryable`/`IEnumerable` source requirement, so queries are pure, container-independent module-level values; (d) the F# spec quirk that `Run` overloads resolve through `LowPriority`/`HighPriority` extension modules is reproduced for scalar terminals. Rejected alternative: inheriting `QueryBuilder` – verified to work, kept as a fallback if users demand literal `query { }` compatibility (a thin subclass could forward to the same translator).

## 4. Layered architecture and data flow

```text
user code   cosmosQuery { for p in items<Person> do where (p.Age > minAge); sortBy p.Name; take 10; select {| … |} }
            Query.where <@ fun (p : Person) -> p.Nick.IsSome && p.Tags |> List.contains "vip" @>
                                │ Expr
[1] Front end      CosmosQueryBuilder (Quote/Run) · Query.* functions · CosmosQuery.compile/ofReflected      Quotations pkg
                                │ CosmosQuery<'T> = { Expr; Cardinality }  (pure, container-independent)
[2] Normalizer     pipes, composition, beta, let-inlining, ReflectedDefinition, witnesses, copyOfStruct,
                   $"…", 2m, &&/||, tuple/record projection elimination; bounded fixpoint                    Quotations pkg
                                │ first-order Expr
[3] Parameterizer  Value/ValueWithName/module values/closed subtrees → typed ParameterSlot; shape key        Quotations pkg
                                │ Expr with slot leaves + ShapeKey + slot values
[4] Translator     operator chain → QueryModel → SqlQuery (lowering table); scalar nodes through the
                   registry (user plugins → built-in packs → evaluation fallback)                           Quotations pkg
                                │ SqlQuery (spec model)
[5] Passes         SqlQuery.validate · simplify · alias compaction · partition-key lift · capability lint   Sql pkg
[6] Printer        deterministic text (SDK rendering rules); Parameterize or Inline mode                    Sql pkg
                                │ CompiledPlan { Sql; Slots; Hints; Warnings; Ast }
[7] Cache/binder   ConcurrentDictionary<ShapeKey, CompiledPlan> per Translator; slot values → encoders       Quotations pkg
                                │ QueryDefinition (+ QueryRequestOptions hints)
[8] Execution      Container.GetItemQueryIterator<'T> → FeedIterator<'T>.AsAsyncEnumerable / CancellableTaskSeq
```

Stages 2–6 are pure functions over immutable data; the only mutable state is the plan cache owned by a `Translator` instance; stage 8 is the only place touching the SDK `Container`. Plugins never throw: they return an `Outcome`, and the engine converts failures into positioned diagnostics.

**Why an intermediate `QueryModel` between `Expr` and `SqlQuery`:** Cosmos clause order is not free (`take` then `skip`, `select` after `distinct`, aggregates after paging, `TOP` illegal in subqueries, `OFFSET` requires `LIMIT`, `groupBy` last). One immutable record lowered in one place with a unit-tested "re-nest or reject" table avoids the SDK's `Take().Skip()` bug and Marten's outer-to-inner rewrite hacks. All front ends (CE, `Query.*`, compiled queries, later `Seq` pipelines) share this pivot so semantics cannot drift.

**Why a separate SQL AST instead of printing while walking the quotation:** structural rewrites (partition-key lifting, simplification, parameter inlining) are trivial on a DU; the printer is one place with SDK-compatible rules; `parse (print ast) = ast` properties become possible; plugins build SQL through smart constructors instead of strings.

**Collections and allocation rules (maintainer decision).**

- Ordered sequences in data types and public contracts are `ImmutableArray<'T>` (AST children, plugin and translator lists, parameter slots, validation errors, warnings), built with `ImmutableArray.CreateBuilder` or collection expressions, never by repeated `Add`. Precedent in this repo: `ReadManyOperation.Items` (`src/Cosmos/ReadMany.fs:10`).
- Read-mostly lookup tables built once are `FrozenDictionary<'K,'V>`/`FrozenSet<'T>`: the registry index by `MemberKey`, the catalog by function name, keyword and reserved-word sets, type-mapping and member-name tables. String keys always get an explicit comparer (`StringComparer.Ordinal`, or `OrdinalIgnoreCase` for SQL keywords and function names).
- `ImmutableDictionary`/`ImmutableList` only where persistent updates are really needed; the plan cache stays a `ConcurrentDictionary`.
- **Structural equality is not free with `ImmutableArray`**: it is a struct whose `Equals` compares the underlying array reference, so an F# record or union holding one loses structural equality silently. AST nodes therefore hold `EquatableArray<'T>` – a small struct wrapper over `ImmutableArray<'T>` with sequence equality and a combined hash code (the pattern Roslyn incremental generators use) – which keeps compiler-generated equality on the unions correct for round-trip tests, cache keys and pass idempotence. A unit test asserts `parse (print ast) = ast` on nodes with children so a regression cannot hide.
- Pattern matching stays readable through struct partial active patterns over `ImmutableArray` whose payloads are struct tuples, not by converting to F# lists: `[<return: Struct>] let (|Arr2|_|) (xs : ImmutableArray<'T>) = if xs.Length = 2 then ValueSome (struct (xs[0], xs[1])) else ValueNone`, matched as `Arr2 (a, b)` or `Arr2 (struct (a, b))`; `Arr3` alike, `Arr1 a` with the bare element; `Arr0` is a bool pattern `let (|Arr0|_|) (xs : ImmutableArray<'T>) = xs.IsEmpty`; other lengths fall through to the next case. `[<return: Struct>]` makes only the `voption` a struct: a payload written `ValueSome (xs[0], xs[1])` gives `ValueOption<Tuple<_, _>>`, one heap tuple per match, and a multi-case pattern `(|Arr0|Arr1|ArrN|)` returns a heap `Choice` *(verified in fsi)*. F# lists remain where FSharp.Core itself hands them out – `Patterns.Call (target, method, args)` yields `Expr list` – and in the few places where a list pattern is clearly more readable than the alternative.
- User-facing marker functions take `'T seq`, so callers may pass arrays, lists or immutable collections inside quotations.
- Tests and generators may use F# collections freely.

**Multi-value data (maintainer decision 2026-09-27: prefer struct tuples).**

- Values grouped inside the implementation – pass results, registry and cache keys, collection elements, active-pattern payloads, bind-time slot values – are struct tuples `struct ('a * 'b)` (for example the parameterizer's result: rewritten `Expr`, `ShapeKey`, slot values), or `[<Struct>]` records when the fields have meanings and travel through several functions: the symbolic optional pair `OptionalPair` (§9), the `MemberKey` identity (§8), `SourceRange` (§12). Never a reference tuple.
- Public functions and members that return several values return anonymous struct records `struct {| … |}` (`QueryPageAsync`, §15) or named records (`Page`, §9a), never tuples. Collection elements in public contracts are `ImmutableArray<struct (…)>` (`NativeOperations`, `TypeMapping.Members`), in AST nodes `EquatableArray<struct (…)>` (`ObjectCreate`). Plugin callbacks receive the parts of a node as one struct tuple after the context (`Translator.forMethod`, §8). Contracts declare no `out` parameters, which F# callers see as reference tuples (`Dictionary.TryGetValue "k"` is a `Tuple<bool, int>` *(verified in fsi)*).
- **Not tuples, unchanged:** union case fields (`Forward of first : int * after : …`); tupled parameters of methods and abstract members (`abstract Translate : TranslationContext * Expr -> Outcome` compiles to a two-parameter method *(verified in fsi)*); CE builder members, which the desugaring calls as `For (source, body)`. Parentheses around an abstract member's parameter list, `abstract M : (A * B) -> C`, compile to one `Tuple` parameter *(verified in fsi)* and are never written.
- **Forced reference tuples** are accepted at the boundary, destructured at once and never stored: the payloads of FSharp.Core `Patterns.*` (`Call`, `Value`, `ValueWithName`, `WithValue`, `PropertyGet`, … return `(… * …) option`); `FSharpType.GetFunctionElements` and `FSharpValue.GetUnionFields`; the CE variable space (§7); the bodies of `[<ReflectedDefinition>]` functions and static members with tupled parameters; `fst`/`snd`, `||>`/`|||>`/`<||`/`<|||`, `.Item1` (compiles only on reference tuples, with warning FS3220) and the `KeyValue` pattern (`Call (KeyValuePattern)` returning `Tuple<'K, 'V>`); the FSharp.Core collection functions `zip`/`zip3`/`unzip`/`indexed`/`pairwise`/`countBy`/`groupBy`/`partition`/`allPairs`/`mapFold`/`splitAt`/`unfold`, `Map.toSeq`/`toList`/`toArray`/`ofSeq`/`ofList` and `dict`; `out`-parameter results; the `DebugRange` quotation attribute (`Tuple<string, Tuple<string, int, int, int, int>>`, converted once into `SourceRange`) *(all verified in fsi)*. A reflection scan of the public methods of FSharp.Core 10.0.100 finds `ValueTuple` only in the `MergeSources` overloads of `TaskBuilder` and `BackgroundTaskBuilder` (`and!`) *(verified)*. F# never converts a tuple value from one kind to the other (FS0001); a syntactic `(a, b)` is compiled as a struct tuple only where a struct tuple is already the expected type *(verified in fsi)*.
- **Rewrites keep the tuple kind.** `Patterns.NewTuple` also matches struct tuples, but `Expr.NewTuple` always builds `System.Tuple`: rebuilding a struct node with it changes `Expr.Type`; a `Let` or `Call` that receives the rebuilt node as its bound value or argument then throws `ArgumentException`, while as a `Let` body the change passes silently *(verified in fsi)*. Rebuilds go through `ExprShape.RebuildShapeCombination` or, when `Type.IsValueType`, `Expr.NewStructTuple`; both keep `ValueTuple` *(verified in fsi)*. The pinned FSharp.Core 10.0.100 already exposes `NewStructTuple` and `Expr.NewStructTuple` without an assembly argument *(verified by reflection)*.
- User-facing forms – projections, group keys, sort keys, keyset keys – are in §20.11; compiled-query arguments in §7.

## 6. The spec model: `FSharp.Azure.Cosmos.Sql`

**AST.** One DU case per `sql.g4` non-terminal, named after the SDK `SqlObjects` classes so SDK baselines, parser baselines and the OfflineEngine port line up 1:1: `SqlQuery` (Select, Distinct, Top, From, Where, GroupBy, OrderBy/OrderByRank, OffsetLimit), `SelectSpec` (Star/Value/List), `CollectionExpression` (Aliased/ArrayIterator/Join), `Collection` (InputPath/Subquery), `PathExpression`, `ScalarExpression` (Literal, ParameterRef, PropertyRef, MemberIndexer, Binary, Unary, Conditional, Coalesce, In, Between, Like, FunctionCall, ArrayCreate, ObjectCreate, Exists, Array, All, First, Last, Subquery), `Literal` (Boolean, Null, Undefined, Int of int64, Float, String), `BinaryOperator` (17 kinds; `Coalesce` is its own scalar case), `UnaryOperator` (4). Rules: immutable records/DUs whose child collections are `EquatableArray<'T>` (§4), so structural equality holds for round-trip tests, cache keys and pass idempotence; **no raw-text case** – the escape hatch is parsed (below); **no shift operators** (`sql.g4` lacks `<< >> >>>`; F# shifts map to `INTBITLEFTSHIFT`/`INTBITRIGHTSHIFT`); inline `Int` literals outside ±2^53 are errors unless `Semantics.AllowLossyInt64` (parameters are never range-checked; they only warn `CQ1005`); decimals are always parameters.

**Validator.** `SqlQuery.validate : SqlQuery -> ValidationError list` encodes rules the grammar cannot: `SELECT *` only with one alias; `OFFSET`+`LIMIT` together, literal or parameter; `TOP` never in a subquery; parameters only in scalar/TOP/OFFSET/LIMIT positions; `ORDER BY` items only property paths or catalog functions flagged `AllowedInOrderBy` (`VectorDistance`, scoring functions) and parameter-free; `GROUP BY` keys parameter-free; no `OFFSET`/`LIMIT`/`ORDER BY` inside subqueries; `ORDER BY RANK` items only scoring functions and never mixed with plain items; aliases `[A-Za-z_][A-Za-z_0-9]*` and not keywords; `IN` non-empty; object-literal keys string literals; GROUP BY projections grouped or aggregated. Nothing unvalidated reaches the printer.

**Printer.** Copies `SqlObjectTextSerializer` rules *(verified)*: bare alias identifiers; every property access as `alias["name"]` with JSON escaping (safe for reserved words such as `value` – the 1.1.0 changelog fix – and arbitrary keys; `PropertyStyle.DotWhenSafe` optional); every binary/unary/conditional/coalesce/IN/BETWEEN/LIKE node parenthesised; strings double-quoted with `\\ \" \/ \b \f \n \r \t` and `\uXXXX` for control characters; integers via `long`, doubles via `R`/`InvariantCulture`; lowercase `undefined/null/true/false`; `udf.` prefix; clause order `SELECT [DISTINCT] [TOP n] spec FROM … WHERE … GROUP BY … ORDER BY [RANK] … OFFSET n LIMIT m`. Output is byte-comparable with SDK and EF baselines; total and culture-independent (tested under `fr-FR`). Two modes: `Parameterize` (default) and `Inline` (a `substituteParameters` pass replaces `ParameterRef`s with literal ASTs from each slot's `ToLiteral` encoder; used for `Patch.filterPredicate` – `src/Cosmos/Patch.fs:98/209` takes a plain string *(verified)* – and diagnostics).

**Catalog as data.** `FunctionSpec = { Name; Category; Arity; ReturnKind; UndefinedRule; IndexUsage; Availability : Service|WindowsEmulator|VNextEmulator; Deterministic; OnlyInOrderByRank; DocUrl }` for the ~135 documented functions (seeded from the SDK `SqlFunctionCallScalarExpression.Names` minus internal names, and the Learn pages – note the docs index omits `NOW, AGO, DATETIMEFORMAT, YEAR, MONTH, DAY, LASTINDEXOF, SETDIFFERENCE, SETEQUAL`), plus `OperatorSpec` (precedence, JS-int32 flag) and `KeywordSpec`. `Catalog.call name args` validates arity and placement at translation time. The same table drives translators, the interpreter, emulator capability gating, index-usage advice and the generated coverage page. The coverage test is scoped: from Phase 1 it asserts every registered rule references a catalog entry; from Phase 4 it flips to "every entry is `Supported` (rule + golden test) or `Unsupported of reason`".

**Scalar parser (shipped, hand-written).** `Sql.Parser.parseScalar : string -> Result<ScalarExpression, ParseError>` – small recursive descent over the `sql.g4` scalar grammar (no FParsec, no runtime dependency). Backs `Cosmos.Functions.raw` so raw text is parsed, hole-substituted and validated instead of spliced, and gives `parse (print ast) = ast` properties. The ANTLR-generated parser in tests remains the *independent* oracle.

## 7. Front end and normalisation

**Four entry points, one pivot, one normalizer.**

1. `cosmosQuery { for p in items<Person> do where (…); sortBy p.Name; thenByDescending p.Age; skip 20; take 10; select {| Name = p.Name |} }` – standalone builder (§3). `Run` returns a **pure** `CosmosQuery<'T>` (quotation + result cardinality), not results. `items<'T>` is a phantom source; the container is supplied at execution, so queries are container-independent, cacheable module-level values, testable without a client. Operations: `where`, `select`, `sortBy`, `sortByDescending`, `thenBy`, `thenByDescending`, `skip`, `take`, `top`, `distinct`, `count`, `exists`, `head`, `headOrDefault`, `sumBy`/`averageBy`/`minBy`/`maxBy`, `groupBy … into`, `orderByRank`, `withPartitionKey`; nested `for l in p.Lines do` lowers to `JOIN l IN p["lines"]`. *(verified)* F# 10 accepts `[<CustomOperation>]` on extension members of a builder type, so plugin packages may add keywords, but the primary plugin surface is marker functions inside `where`/`select`/`orderByRank`.
2. Functional API: `Query.where <@ fun p -> … @>`, `Query.select`, `Query.sortBy`, `Query.take`, `Query.skip`, … composing `CosmosQuery<'T>` values – for pipeline-style users and for `Patch.filterPredicate`.
3. Compiled queries: `CosmosQuery.compile translator <@ fun (args : {| MinAge : int; City : string |}) -> cosmosQuery { … } @>` and `CosmosQuery.ofReflected <@ Queries.adults @>` (body pickled by fsc at build time via `[<ReflectedDefinition>]`, cached by FSharp.Core per method token). `compile` also accepts curried, struct-tupled and reference-tupled argument lambdas; the documented tupled form is `fun (struct (minAge, city)) -> …`, so `Definition` takes its arguments without a heap tuple. Both tupled forms arrive in the shapes of the `betaReduce` row below *(verified in fsi)*: each component becomes the slot named after its `Let` variable, found by `Var` identity and tuple index, never by the order of the `Let`s (a struct pattern binds in descending order of the variable names) or by the number in `_argN`. A lambda over two documents is `InvalidQueryShape` (no cross-document join).
4. Auto-quoted method arguments *(verified in fsi)*: a member whose parameter is declared `[<ReflectedDefinition>] predicate : Expr<'T -> bool>` receives the quotation of an ordinary lambda, so callers write `container.ExistsWhereAsync (fun d -> d.Email = email)` or `query.Where(fun d -> …).SortBy(_.Name)` without `<@ @>`. Plain lambdas, the `_.Member` shorthand, function references and point-free compositions all arrive as quotations with captured values as `ValueWithName`; `[<ReflectedDefinition(true)>]` yields `WithValue (compiledFunction, quotation)`. Limits: the same member does not accept a quotation value (type error), so quotation values go through `Query.*`; a function value passed by name is quoted as a reference to the value → `CapturedFunctionValue` unless the function is `[<ReflectedDefinition>]`. The fluent members (`Where`, `Select`, `SortBy`, `SortByDescending`, `ThenBy`, `ThenByDescending`, `GroupBy`) are intrinsic members of `CosmosQuery<'T>`/`OrderedCosmosQuery<'T>`, never `[<AutoOpen>]` extensions on shared types such as `IQueryable<'T>` (the Marten layer's extensions shadow `System.Linq.Queryable`).

A `Seq`/`List` pipeline front end (`items |> Seq.filter … |> Seq.sortBy … |> Seq.truncate n`) lowers to the same `QueryModel` in Phase 2.

**Composing quotations.** Quotation splicing is the composition mechanism for reusable fragments: `let adult = <@ fun (p : Person) -> p.Age >= 18 @>` then `where ((%adult) p && p.City = city)`. Typed `%` and untyped `%%` splices arrive as `Application (Lambda (p, body), arg)` *(verified)* and are beta-reduced by the normalizer; captured values inside the spliced quotation stay `ValueWithName` slots, so the shape key and parameterisation are unaffected. On top of splicing the functional API ships combinators that build quotations: `Predicate.and'`, `Predicate.or'`, `Predicate.not'`, `Predicate.all`/`Predicate.any` over a list of predicates, and conditional filters `Query.whereIf condition predicate` / `Query.whereSome (value : 'V voption) (fun v -> <@ … @>)`, so dynamic predicate building never needs string concatenation. Point-free predicates (`Query.where <@ isAdult @>`, `<@ (=) userId @>`, `<@ not << isAdult @>`) are accepted through `etaExpand`.

**SQL alias** = the F# lambda variable name when it is a safe identifier and not a keyword (`value`, `order`, `left`, `right`, `first`, `last`, `all`, `in`, `top`, `rank`, `group`, `by`, `escape`, …), otherwise `c`; inner aliases from element lambda names, uniquified. Generated SQL that reads like the source helps logs, index metrics and support. A variable name is *generated* when it does not match the identifier pattern, starts with `_arg` (the `_.Member` shorthand and the struct-tuple pattern `fun (struct (a, b)) -> …` yield `Lambda (_arg1, …)` *(verified)*) or with `activePatternResult` (the `KeyValue` pattern), or is one of `copyOfStruct`, `matchValue`, `tupledArg`, `patternInput` (`let (a, b) = …`, `let struct (a, b) = …`) *(verified in fsi)*; generated names and parameters synthesised by `etaExpand` map to alias `c` (element aliases `t`, `t1`, …). Several `Query.where`/`select`/`sortBy` calls with different variable names are unified to the alias of the first operation. `TranslatorOptions.RootAlias` fixes the root alias for all queries (recommended for golden files and for the service-side plan cache). Variable names never enter the shape key, so point-free, shorthand and explicit-lambda forms of one predicate share one cached plan.

**Normalizer.** Named `Expr -> Expr` passes on `ExprShape`, run to a bounded fixpoint (32 iterations, then `NormalizationDiverged`). Shapes *(verified in fsi)*:

| Pass | Handles |

## 8. Translator, registry and plugin model

**Operator level.** A table maps builder methods (and later `Seq/List/Array` functions on the root source) to `QueryModel = { Alias; Joins; Wheres; Orderings; RankOrdering; Skip; Take; Distinct; Projection; Terminal; PartitionKey }` with explicit variable substitution. Lowering applies an explicit re-nesting table written from the Phase 0 results (§16), which both emulators give alike *(verified, #44)*. A `FROM (SELECT VALUE …) AS x` subquery may hold a filter, a projection, `DISTINCT` or `GROUP BY` and may be nested, and the query around it may filter, project, aggregate, use `DISTINCT`, and sort and page with `ORDER BY`, `TOP` and `OFFSET LIMIT`; so `select` then `where`, `distinct` then an aggregate, and a filter over the groups of a `GROUP BY` (§20.10) re-nest. `TOP`, `ORDER BY` and `OFFSET LIMIT` are rejected inside every subquery, in `FROM`, `EXISTS`, `ARRAY` and scalar position alike (errors SC2203, SC2202, SC2204), and an `ORDER BY` outside a subquery accepts only a path of the documents, not a value the subquery computes (error 2206). So `take`, `skip` or `sortBy` followed by `where`, `distinct` or an aggregate cannot re-nest and is `InvalidQueryShape` with a documented workaround (filter before paging, or page on the client), and a sort by a value a subquery computes is `OrderByNotPath`. Shapes outside the table stay `InvalidQueryShape` until a probe promotes them; the native planner on the Windows lane remains a later oracle; `head`/`headOrDefault` → `TOP 1` + `Cardinality.Single`; `exactlyOne` → `TOP 2` + client check; `skip` without `take` → `OFFSET @m LIMIT 2147483647` with warning `CQ1020 SkipWithoutTake`; `groupBy` is followed only by its projection, which may only use the group key and aggregates, and by a filter over the projected groups (§9, §20.10). `OperatorRule`s are registrable so plugin keywords can participate.

**Scalar level.** The engine handles structural nodes itself (`Var`, `Let` residue, `IfThenElse`, `NewTuple/NewRecord/NewArray/NewUnionCase` → literals through type mappings, `NewTuple` of either tuple kind in the form that `TupleEncoding` reports for its type and target member (§10), `Coerce` erase, `TypeTest` → `IS_*`, `UnionCaseTest` → layout-driven tag tests, `TupleGet` over a tuple-typed document path → the component path that `TupleEncoding` gives: `path[i]` under `Array`, `path["Item<i+1>"]` through the naming policy with a nested `Rest` from the eighth component under `ItemObject`, `MemberNotSerialized` under `ValueNone` and `LayoutRequired` under `Opaque` (§10, §20.12)). For `Call`, `PropertyGet`, `FieldGet`, `NewObject`, `NewUnionCase`, `UnionCaseTest` it computes a `MemberKey` (`Method` of generic definition, `Property`, `Field`, `Constructor`, `UnionCase`, `OfType`; compared by module, metadata token and generic arity, held in one `[<Struct>]` key) and dispatches: exact-key index (user plugins first, then built-in packs) → pattern translators (`Keys = []`, e.g. "any member whose declaring type is assignable to a registered geometry type") → evaluation fallback per `EvaluationPolicy` → `Unsupported` error listing the member, the translators consulted and the escape hatches. `Translator.Explain` returns the per-node trace.

**`TranslationContext`** (given to every translator; linq2db's `ITranslationContext` collapsed into one interface with smart constructors): `Translate`/`TryTranslate`, `Parameter (value, clrType, nameHint)`, `Literal`, `Mapping : Type -> TypeMapping`, `Layout : IJsonLayout`, `Semantics`, `Call (name, args)` (catalog-validated), `Member (target, MemberInfo)` (layout-resolved path), `CanEvaluate`/`Evaluate`, `NewAlias`, `TranslateSubquery`, `Options`, `Warn`, `Fail`.

**Plugin record and conflict rules.**

```fsharp
type TranslatorPlugin =
    { Id : string; After : ImmutableArray<string>; Before : ImmutableArray<string>
      ScalarTranslators : ImmutableArray<IScalarTranslator>; OperatorTranslators : ImmutableArray<IOperatorTranslator>
      TypeMappings : ImmutableArray<ITypeMappingProvider>; GeometryProviders : ImmutableArray<IGeometryProvider>
      NonEvaluatable : ImmutableArray<MemberKey>; CatalogExtensions : ImmutableArray<FunctionSpec> }
and IScalarTranslator =
    abstract Id : string
    abstract Keys : ImmutableArray<MemberKey>      // empty => pattern translator
    abstract Overrides : ImmutableArray<string>
    abstract Translate : TranslationContext * Expr -> Outcome
and [<RequireQualifiedAccess>] Outcome = Translated of Translated | NotApplicable | Failed of TranslationError
```

Two tiers only: user plugins (registration order refined by `After`/`Before` via topological sort; cycles throw) and built-in packs (themselves plugins, so the coverage test and conformance kit treat them uniformly). Enforced at `Translator.Create`, never silently: two exact translators in the same tier sharing a key where neither lists the other in `Overrides` → `RegistryConflictException` naming both; a plugin translator on a key also owned by a built-in simply wins; two `GeometryProviders` claiming overlapping types → conflict unless one `Overrides` the other; unknown ids → exception. Type-mapping providers form an ordered chain (plugins first), first `ValueSome` wins. Translators are immutable singletons (linq2db lesson: per-call instances poison caches). No global mutable registry (the rejected branches had one).

**Two registration routes.** Attribute route (itself a built-in pattern translator): `[<CosmosSql "STRINGEQUALS({0}, {1}, true)">]` templates with `{n}`/`{this}` holes (parsed by the shipped scalar parser), `[<CosmosFunction "MyFn">]`, `[<CosmosUdf "isVip">]` on stubs whose body is `Cosmos.Functions.clientOnly ()` (throws outside a quotation, like `EF.Functions`). Programmatic route: `Translator.forMethod <@ f @> (fun ctx (struct (this, args)) -> …)` with `forMethod : Expr -> (TranslationContext -> struct (Expr voption * ImmutableArray<Expr>) -> Outcome) -> IScalarTranslator`; the receiver is converted once from the `Expr option` of `Patterns.Call` and the arguments from its `Expr list` *(verified in fsi: the lambda compiles against this signature, while the reference pattern `(this, args)` makes the callback take a `Tuple<FSharpOption<Expr>, FSharpList<Expr>>`, one heap tuple per translated node)*. `forProperty` (`struct (Expr voption * PropertyInfo)`), `forUnionCase` (`struct (UnionCaseInfo * ImmutableArray<Expr>)`) and the `TypeMapping.Equality`/`Containment` hooks of §20.8 (`struct (Expr * Expr)`) follow the same convention: context first, then one struct tuple of the node parts; `forType`, `pattern` and `TypeMapping.provider` complete the route.

**Geometry without binding to a library.** Core defines abstract operations and generic markers: `Cosmos.Geo.distance : 'G -> 'G -> float`, `within`, `intersects`, `isValid`, `isValidDetailed`, `area` (→ `ST_*`), a neutral `GeoShape = Point | LineString | Polygon of rings | MultiPolygon` DU with a core GeoJSON writer (`[lon, lat]`, ring-orientation warning), and

```fsharp
type IGeometryProvider =
    abstract Id : string
    abstract GeometryType : Type
    abstract Overrides : ImmutableArray<string>
    abstract ToShape : obj | null -> GeoShape voption
    abstract NativeOperations : ImmutableArray<struct (MemberKey * NativeGeoRule)>   // opt-in: `point.Distance other` in library style
and NativeGeoRule = { Operation : GeoOperation; Arguments : ArgumentOrder }   // ReceiverFirst | ReceiverLast | Swap | Custom of (Expr list -> Expr list)
```

A document field typed as geometry is a plain path; a captured geometry value becomes a `RawJson` parameter (`WithParameterStream`) written by the core from the provider's `GeoShape`, which every spatial function accepts *(verified on the Windows emulator, #44)*; comparisons between two members need no provider at all. `NativeOperations` carries an argument-order rule (NTS `polygon.Contains point` is `ST_WITHIN(point, polygon)`; `Covers`/`CoveredBy` swap arguments) and warning `CQ1008 NativeGeometrySemantics` (NTS distance is planar, `ST_DISTANCE` is metres on the WGS-84 ellipsoid – 110 574 m for one degree of latitude at the equator *(verified on the Windows emulator, #44)*). Storage side, documented and tested by the conformance kit: NTS-typed document fields require `NetTopologySuite.IO.GeoJSON4STJ` converters on the client's STJ options (STJ-only, no Newtonsoft dependency); they cannot be stored with the SDK's Newtonsoft default. A third-party library plugs in with ~20 lines (§15). This is EF's NTS plugin contract (type-mapping + method translators + evaluatable filter) re-keyed on abstract operations instead of one library's `MethodInfo`s.

**Vector, full text, UDF, raw** are part of the language, so their markers live in core `Cosmos.Functions`: `isDefined`, `isNull`, `coalesceUndefined` (`??`), `iif`, `regexMatch`, `arrayContains`/`arrayContainsPartial`/`arrayContainsAll/Any`, `documentId`, `now ()` (`GetCurrentDateTime()`), `vectorDistance a b bruteForce options` – generic over the vector element type with type mappings for `float32[]`, `byte[]`, `sbyte[]`, `Half[]` and `ReadOnlyMemory<_>` (the SDK offers `byte[]`/`sbyte[]`/`float32[]` overloads; the service also supports float16/quantized types); `options` is a core `VectorDistanceOptions` record (`DistanceFunction`, `DataType`, `SearchListSizeMultiplier`, `QuantizedVectorListMultiplier`, `FilterPriority`) rendered inline as the service requires – the core never references `Microsoft.Azure.Cosmos.Linq` (the SDK's options type is the nested `CosmosLinqExtensions.VectorDistanceOptions`); per-field metadata via `[<CosmosVector(DistanceFunction.Cosine, VectorDataType.Float32)>]` (SDK enums from the root namespace) or `Options.VectorFields`, `fullTextContains/All/Any`, `fullTextScore`, `rrf`, `udf<'R> name args`, `raw<'R> sql args` (Marten `MatchesSql` style with `{n}` holes; parsed, substituted, validated). Scoring functions are catalog-flagged `OnlyInOrderByRank`; `orderByRank` validates this and inlines OFFSET/LIMIT constants there (EF `ParameterInliner` lesson). All markers are deny-listed from client evaluation.

**Custom scalar types.** `TypeMapping = { ClrType; JsonType; ToParameterValue : obj -> ParameterValue (Object | RawJson); ToLiteral : obj -> ScalarExpression voption; IsOrderable; Element }`. Units of measure are erased by the compiler (nothing to do); single-case DUs, enums, `DateTimeOffset`/`DateOnly`/`TimeOnly`/`Guid`, `decimal`, `int64` get built-in mappings with encodings from the layout; user value types register a provider. F# nullness is enabled repo-wide (`<Nullable>enable</Nullable>`), so value-carrying members are typed `obj | null` (`TypeMapping.ToParameterValue`, `IGeometryProvider.ToShape`, `TranslationContext.Evaluate`/`Parameter`); a `null` slot value becomes `ParameterValue.Object null` → JSON `null`, and null-valued slots are covered by the conformance kit and the differential generators.

## 9. Semantics decisions (documented truth tables, all tested)

`Semantics = { Null : Typed | Strict | Native; Division : IntegerAware | Native; StringConcat : ConcatFunction | Operator; CultureComparison : Reject | AsOrdinal; AllowLossyInt64 : bool }` is explicit, part of the plan-cache key, `Typed` by default.

- **Null/undefined (`Typed`).** Guards are inserted exactly where the CLR type says a value may be absent (`option`, `voption`, `Skippable`, `Nullable`, nullable reference members); non-optional record fields are assumed present, so their comparisons carry no guard; a guard costs little anyway and keeps the index seek of the comparison it protects *(verified on the Windows emulator, §16)*. `Strict` guards every comparison; `Native` emits bare operators (documented: `undefined` excludes the item). Guard forms for an optional member `p` (robust; narrowed only with `TranslatorOptions.NarrowOptionalGuards`, §20.12): has value → `(IS_DEFINED(p) AND NOT IS_NULL(p))`; no value → `(NOT IS_DEFINED(p) OR IS_NULL(p))`; `Skip` → `NOT IS_DEFINED(p)`; `Include None` → `IS_NULL(p)`; `inner(p)` = `p` for unwrapped encodings or the field path for `CaseFields`. Everything else – equality, ordering, unwrapping and every `Option`/`ValueOption`/`Skippable` function – follows from the pair rules of the next bullet and of §20.3–§20.5. `??` is emitted only through `Cosmos.Functions.coalesceUndefined`: it replaces only `undefined` and keeps an explicit `null` *(verified on both emulators, #44)*, so it never translates `Option.defaultValue`, whose `None` may be stored as `null`.
- **Optional values are translated symbolically** as a pair of scalar expressions (internally `[<Struct>] OptionalPair = { HasValue : ScalarExpression; Value : ScalarExpression }`, §4; `(h, v)` here, in §9a and in §20 is notation, not a type) rather than by per-function rules – for `option`, `voption`, `Skippable`, `Nullable` and nullable references alike. A member gives `(isSome(p), inner(p))`; `Some e`/`ValueSome e`/`Include e` give `(true, e)`; `None`/`ValueNone`/`Skip` give `(false, undefined)`; `map f` → `(h, f v)`; `bind f` → `(h AND h', v')`; `filter q` → `(h AND q v, v)`; `orElse y` → `(h OR hy, (h ? v : vy))`; `exists q` → `h AND q v`; `forall q` → `NOT h OR q v`; `contains x` → `h AND v = x`; `defaultValue d`/`defaultWith` → `(h ? v : d)`; `get`/`.Value` → `v`; `isSome`/`isNone`/`.IsSome`/`.IsNone`/`.HasValue` → `h`/`NOT h`; `count` → `(h ? 1 : 0)`; `toList`/`toArray` → `(h ? [v] : [])`; `flatten`; `toObj`/`ofObj`/`toNullable`/`ofNullable`/`toValueOption`/`ofValueOption`/`Skippable.toOption`/`ofOption`/… as pair conversions; `match` arms read the pair. Any composition (`map >> bind >> filter >> defaultValue`, pipelines, point-free forms) therefore works uniformly in `where`, `select`, sort keys and group keys – the maintainer's Marten layer supports these in WHERE only and documents the SELECT failure, an `ArgumentNullException`, in its limitations notes and in a root-cause analysis, which this design must not reproduce: every option test case runs in predicate **and** projection position. The pair is materialised into JSON only when the optional value itself is projected or compared as a whole, using the layout's encoding (`null`, omitted member, or `{"Case": "Some", "Fields": [v]}` when `UnwrapOption` is off), so a projected `option` deserialises back through the same serializer.
- **Numbers.** `int/int` → `INTDIV(a, b)`, `int % int` → `INTMOD`: both truncate toward zero like F# `/` and `%` on integers, and a zero divisor or a fractional operand gives `undefined`, which drops the row (or omits the member) where F# throws – documented divergence *(verified on both emulators, #44)*; floats → `/`, `%`, where a zero divisor gives an infinity that compares as such in a filter but fails the whole query with HTTP 400 once a returned value holds it, because JSON has no infinity or NaN *(verified, #44)* – documented, since .NET returns the infinity; `int32` bitwise → `& | ^ ~` (JS-int32 semantics coincide); `int64` bitwise → `INTBITAND/OR/XOR/NOT`; all shifts → `INTBITLEFTSHIFT/RIGHTSHIFT`; `decimal` always a parameter with warning `CQ1004 DecimalPrecision`; `int64` beyond 2^53 → `CQ1005 Int64Precision`.
- **Strings.** `+` and `$"…"` → `CONCAT(…)` (`||` has the lowest binary precedence in `sql.g4`; `+` is undocumented); `ToString(x)` inserted for non-string holes; ordinal, case-sensitive comparisons; the `StringComparison` argument of `Equals`/`Contains`/`StartsWith`/`EndsWith` follows §20.6 (`Ordinal` equality is `=`, `OrdinalIgnoreCase` is the third argument `true`, culture-sensitive values are rejected unless `Semantics.CultureComparison = AsOrdinal`); `ToLower()/ToUpper()` in predicates warn `CQ1001 FullScanFunction`.
- **Conditionals.** `if/then/else` in value position → `(c ? a : b)` (under `Typed`, conditions on optional members are guarded, so the ternary's undefined trap cannot fire); in predicate position → `((c AND a) OR (NOT c AND b))`; `match` on unions → nested conditionals over layout-provided tag paths; `IIF` only via `Functions.iif`.
- **Collections.** `List/Array/Seq.contains v p.Tags` → `ARRAY_CONTAINS(p["tags"], @v)`; `values |> List.contains p.X` with a captured list → `ARRAY_CONTAINS(@values, p["x"])` (stable SQL text, served from the index at the cost of the equivalent `IN` *(verified on the Windows emulator, §16)*); a source-literal list → `p["x"] IN (@p0, @p1, …)` up to `InlineInThreshold` (32); `exists` → `EXISTS(SELECT VALUE t FROM t IN p["tags"] WHERE …)`; `forall` → `NOT EXISTS(… WHERE NOT (…))`; `length`/`.Length`/`.Count` → `ARRAY_LENGTH`; `isEmpty` → `(ARRAY_LENGTH(x) = 0)`; `xs[i]` → `x[i]`; `List.map/filter/sumBy` in projections → `ARRAY(SELECT VALUE … FROM t IN …)`/`(SELECT VALUE SUM(…) FROM t IN …)`; `List.exists (fun t -> t.Name = "x")` over object arrays stays `EXISTS`, which uses the index exactly like `arrayContainsPartial` *(verified on the Windows emulator, §16)*. The same rules apply to `System.Linq.Enumerable` extension methods (`Any`, `All`, `Contains`, `Count`, `Where`, `Select`, `First`…; their F# lambdas arrive as `NewDelegate` *(verified)*) and to BCL collection instance members (`List<T>.Contains/Exists/TrueForAll/Count`, `HashSet`/`ISet`/`ImmutableArray`/`ImmutableList`/`ImmutableHashSet`/`ImmutableSortedSet`/`FrozenSet.Contains`, `Array.Length`, `ICollection.Count`) and to the module functions of FSharp.Collections.Immutable (recognised by name, no package dependency), for document members and captured collections alike.
- **Projections.** Always `SELECT VALUE`: identity → `SELECT VALUE p`; scalar → `SELECT VALUE expr`; records/anonymous records/`{ p with … }` → `SELECT VALUE {"key": expr, …}` with keys from the *target* type's layout names so the same serializer reads them back (fixes SDK #3728); tuples of either kind → the form that `TupleEncoding` reports for the tuple type and target member (§10), a positional array or an `Item1`… object; a tuple type reported as not serialised is refused with `MemberNotSerialized` instead of round-tripping to default values (a struct tuple under the plain-STJ layout without `IncludeFields`), an `Opaque` one with `LayoutRequired` (§20.12); the documented positional form is `select struct (a, b)` (an anonymous struct record `select struct {| … |}` instead of a tuple where names are wanted), and its reference twin gives byte-equal SQL wherever `TupleEncoding` answers alike for both tuple types (§7 tuple-kind law, §20.11); warning `CQ1006 UndefinedInProjection` when a projected member is optional (objects drop undefined members, arrays shift; a tuple array of the wrong length or with `null` in a non-nullable element fails deserialisation under FSharp.SystemTextJson *(verified)*).
- **Paging and ordering.** `take` alone → `TOP @n`; `skip m; take n` → `OFFSET @m LIMIT @n`; `skip` alone → `OFFSET @m LIMIT 2147483647` with warning `CQ1020`; keyset paging in §9a; `take` without `sortBy` warns `CQ1007 NondeterministicTop`; multi-key `sortBy` produces advice `CompositeIndexRequired`; `sortBy` on an optional member needs none, because `ORDER BY` keeps the documents without the value and sorts them where F# sorts `None` – first in ascending, last in descending order (§9a); a tuple sort key – `sortBy (struct (p.Name, p.Age))`, the documented form, or its reference twin with byte-equal SQL – is split into one `ORDER BY` item per component in the operation's direction (`ORDER BY p["name"] ASC, p["age"] ASC`), each component subject to the path rules below; mixed directions need `thenBy`/`thenByDescending` or `SortKey` values; `distinct`/`groupBy` disable continuation (documented). A sort key that unwraps an optional member (`p.Count.Value`, `Option.get`, `Option.defaultValue d`) is lowered to the member path with warning `CQ1011 DefaultIgnoredInOrderBy` – parity with the maintainer's Marten layer, which strips the wrapper for ORDER BY; documents lacking the value sort as `undefined`/`null`, not as `d` – and any other computed sort key is `OrderByNotPath` unless `Options.ComputedProperties` maps the expression to a container computed property.
- **Dates.** Always parameters; contract: stored values and parameters go through the same serializer, so ISO-8601 UTC strings compare correctly; `DateTimeOffset` with non-zero offset warns `CQ1003`; `DateTime.UtcNow` inline is evaluated client-side into a parameter (deterministic, index-friendly); `now ()` is the server-side form. `.Year/.Month/…` → `DateTimePart`, `.AddDays` → `DateTimeAdd`. Cosmos ticks are 100 ns since the Unix epoch, not .NET ticks – rebase in `DateTimeToTicks` mappings.

## 9a. Keyset (seek) paging

The maintainer pages with Relay-style cursors in both projects: the Marten layer has only keyset paging; the Cosmos application is a hybrid, a continuation token inside an opaque cursor while the direction is unchanged and keyset predicates when it flips. A continuation token is forward-only, opaque, bound to the query text and unavailable with `distinct`/`groupBy`; keyset cursors are stable, bidirectional and shareable at the price of a composite index. Both are offered; the docs say when to prefer which. Implementation in Phase 2, emulator probes in Phase 0.

```fsharp
type Cursor<'Id, 'Key> = { Id : 'Id; Key : 'Key }          // 'Key = struct tuple of the sort-key values, or the bare value for one key (item 4)
type PageRequest<'Id, 'Key> =
    | Forward of first : int * after : Cursor<'Id, 'Key> voption
    | Backward of last : int * before : Cursor<'Id, 'Key> voption
type Page<'T, 'Id, 'Key> =
    { Items : ImmutableArray<'T>; StartCursor : Cursor<'Id, 'Key> voption; EndCursor : Cursor<'Id, 'Key> voption
      HasNext : bool; HasPrevious : bool }
```

1. **One N-ary implementation** over the `SortKey` list, no arity overloads (the Marten layer has hand-written overloads for one, two and three keys). With the id as key N+1 the predicate is the lexicographic `OR over i of ((AND over j < i of (k_j = @v_j)) AND (k_i op_i @v_i))`. One ascending key, forward: `SELECT TOP @first VALUE c FROM c WHERE ((c["date"] > @k1) OR ((c["date"] = @k1) AND (c["id"] > @id))) ORDER BY c["date"] ASC, c["id"] ASC`.
2. **Direction matrix.** Forward + Asc → `>` and `ASC`; Forward + Desc → `<` and `DESC`; Backward + Asc → `<` and `DESC`; Backward + Desc → `>` and `ASC`. Backward pages are fetched in inverted order and reversed by the execution extension; `n + 1` rows are fetched to compute `HasNext`/`HasPrevious`.
3. **Tie-breaker.** `FollowFirstKey` (default): the id direction follows the first key, so one composite index serves both sort directions and both page directions. `Ascending` is parity with the Marten layer and needs a second, mixed-direction composite index. `id` is unique only inside a logical partition: a cross-partition keyset needs the partition key among the sort keys or a partition-scoped query, otherwise `InvalidQueryShape`.
4. **Cursor components are separate named slots** (`@k1`, `@k2`, `@id`) encoded by the user's serializer. `'Key` is a struct tuple with one component per `SortKey` (the documented form, as in both of the maintainer's code bases), a reference tuple, or the bare value for a single key (F# has no one-element tuple syntax). It is decomposed with `FSharpType.GetTupleElements`/`FSharpValue.GetTupleFields`, which handle both kinds and flatten 8+ components, never with `FSharpValue.PreComputeTuplePropertyInfo`, which throws on `ValueTuple` *(verified in fsi)*; `Query.page` checks the component types against the key types of `keys` and reports `InvalidQueryShape` on a mismatch. The whole `'Key` is never one value: plain STJ writes a struct tuple as `{}` *(verified)*, so an application that serialises `Cursor<'Id, 'Key>` into an opaque token needs FSharp.SystemTextJson, which writes it as a JSON array, or `IncludeFields = true`. The predicate is built as a scalar tree and goes through the normal translator, so scalar wrappers, optional keys and layout paths follow §8–§10. Ordering operators must therefore work on wrapper keys (string wrappers such as `TypedString<_>`, id wrappers).
5. **Optional keys** follow the Cosmos type order `undefined < null < boolean < number < string`, not PostgreSQL `NULLS LAST`: in `ASC` absent values come first. Each lexicographic branch is built with the pair `(h, v)` and the captured cursor pair; `simplify` removes constant-false branches; the predicate is never short-circuited as a whole (a known defect of the Marten code: paging stops inside the NULL bucket). A keyset over an optional key requires a single absence encoding for that member; under `NullOrUndefined` it is `InvalidQueryShape` with that hint.
6. **Index caveats**: a single-property `ORDER BY` keeps the items whose sort path is undefined and returns them first in ascending order, then sorts by type – undefined, `null`, booleans, numbers, strings, arrays, objects *(verified on both emulators, #44)*. A multi-property `ORDER BY` over a composite index keeps them too, because the index holds a value that marks an undefined path, and sorts every key that way: the documents without the first key come first, and among equal first keys those without the second; the exact inverse of the index returns the exact reverse *(verified on both emulators, #44)*. Such an `ORDER BY` is served only by a composite index whose path sequence and ASC/DESC pattern match exactly or are the exact inverse: the Windows emulator refuses any other mix of directions with HTTP 400 ("does not have a corresponding composite index"), as the documentation of indexing policies says, while the vNext emulator, which has no composite indexes yet, sorts without one *(verified, #44)* – only the Windows lane catches a missing index. `CompositeIndexRequired` prints the required index definition.
7. **Tests.** Property: concatenating all pages, forward and backward, equals the unpaged ordered result, including documents whose keys are absent or null. One golden baseline per row of the direction matrix.

## 10. Serializer and member-naming integration: `IJsonLayout`

Everything that depends on how documents were serialised goes through one service:

```fsharp
type IJsonLayout =
    abstract Identity : string
    abstract MemberName : MemberInfo -> string voption                          // ValueNone = not serialised
    abstract OptionalEncoding : MemberInfo voption * Type -> OptionalEncoding   // option / voption / Nullable / Skippable
    abstract UnionLayout : Type -> ImmutableArray<UnionLayout>     // head = write encoding; tail = accepted legacy read encodings
    abstract CollectionEncoding : MemberInfo voption * Type -> CollectionEncoding voption   // ValueNone = not a JSON array
    abstract MapEncoding : Type -> MapEncoding                     // Object | ArrayOfPairs (JsonFSharpOptions.MapFormat)
    abstract Polymorphism : Type -> PolymorphismInfo voption       // discriminator property and values (JsonPolymorphic / JsonDerivedType)
    abstract EnumEncoding : Type -> EnumEncoding                   // String when a JsonStringEnumConverter applies
    abstract TupleEncoding : MemberInfo voption * Type -> TupleEncoding voption   // per tuple type and member ([<JsonConverter>] on a class property is honoured); ValueNone = not serialised ({} under plain STJ)
// OptionalEncoding = NullOrUndefined | AlwaysNull | AlwaysUndefined | CaseFields of tag * FieldLayout   (JsonFSharpOptions without UnwrapOption)
// UnionLayout      = ScalarWrapper | Cases of tag : TagPlacement * fields : FieldLayout
// TagPlacement     = Adjacent of tagName | Internal of tagName | External | Untagged | BareString
// FieldLayout      = Positional of fieldsName | Named of fieldsName | UnwrappedSingleField of fieldsName | UnwrappedRecord | NoFields
// CollectionEncoding = { Element : Type; Empty : AlwaysArray | NullWhenEmpty | OmittedWhenEmpty | NullOrOmittedWhenEmpty }
// TupleEncoding    = Array (positional, arity 8+ flattened, exact length) | ItemObject (Item1…Item7 + nested Rest, through the naming policy) | Opaque (another converter, §20.12)
```

Keyed by member because FSharp.SystemTextJson's `SkippableOptionFields`/`WhenWritingNull` apply to record fields and per-type overrides exist *(verified in the FSharp.SystemTextJson sources)*.

**Tuples are resolved per type and member** because the two kinds serialise differently outside FSharp.SystemTextJson *(verified: STJ 10.0 and FSharp.SystemTextJson 1.4.36, round trips run)*. `JsonFSharpConverter` – one flag, `JsonFSharpTypes.Tuples`, on by default, covers both kinds – writes `(1, "a")` and `struct (1, "a")` as `[1,"a"]`, also under the production profile (§21.3), flattens arity 8+ into one array and reads back only an array of exactly that length. Plain STJ writes a reference tuple as `{"Item1":1,"Item2":"a"}` and a struct tuple as `{}` (`ValueTuple` has fields, no properties), and reads any object into a struct tuple as default values without an error; `IncludeFields = true` makes both kinds `{"Item1":…}` with a nested `"Rest"` from arity 8. The naming policy applies to these names (`SnakeCaseLower`: `item1`, `rest`), and they are matched case-sensitively. A user converter for one tuple type, placed before `JsonFSharpConverter`, changes that type alone. `JsonFSharpOptions` per-type overrides never reach tuples, and FSharp.SystemTextJson 1.4.36 ignores a member-level `[<JsonConverter>]` on an F# record field, but STJ honours it on class properties under both layouts and on record fields under plain STJ *(verified)*. So `fSharpSystemTextJson` answers `Array` for both kinds, `Opaque` (§20.12) when `options.GetConverter` returns a converter that does not come from the FSharp.SystemTextJson assembly (its tuple converters are `JsonTupleConverter`/`JsonStructTupleConverter`) or when a class property carries `[<JsonConverter>]`, and the plain-STJ answer when the `Tuples` flag is off; `systemTextJson` answers `Opaque` for a type-level or member-level converter, `ItemObject` for reference tuples, and for struct tuples only when `IncludeFields` is set, otherwise `ValueNone`. Under `MapFormat.Object` a `Map` with a tuple key of either kind cannot be serialised at all (`NotSupportedException`), so such members are refused; under the default `ObjectOrArrayOfPairs` the key follows `TupleEncoding` (`[[[1,"a"],10]]`). `KeyValuePair` is not a tuple for either serializer: it is the object `{"Key": …, "Value": …}` with policy names.

Implementations:

- `JsonLayout.fSharpSystemTextJson options` – **the supported layout.** Finds the `JsonFSharpConverter` in `options.Converters` and reads its public `Options : JsonFSharpOptions` member *(verified in the FSharp.SystemTextJson sources, `src/FSharp.SystemTextJson/All.fs`)*: `JsonUnionEncoding`, `SkippableOptionFields`, `JsonName`, `WithOverrides` per type; STJ attributes (`JsonPropertyName`, `JsonIgnore`, `JsonInclude`) and the naming policy; `Skippable<'T>` handled as the real type (cases `Skip`/`Include`, members `isSkip/isInclude/IsSkip/IsInclude`, module functions); narrows the guard forms when the encoding is known (`AlwaysNull` → `IS_NULL(p)` alone).
- `JsonLayout.systemTextJson options` – plain STJ without the F# converter: member names and naming policy only. Option, voption and union members are refused with a `MemberNotSerialized`-class diagnostic that names the missing `JsonFSharpConverter` (STJ 10 writes `Some v`/`ValueSome v` as the bare `v` and `None` as `null`, which this layout does not model, and throws `NotSupportedException` for unions *(verified)*). Struct tuples are refused the same way unless `IncludeFields = true`; reference tuples are `{"Item1": …}` objects (§10, tuples).
- `JsonLayout.ofCosmosLinqSerializer` – names only, over an explicitly supplied base layout, when the user's serializer derives from the public abstract `CosmosLinqSerializer`.
- `JsonLayout.ofClientOptions : CosmosClientOptions -> IJsonLayout` – **auto-detection**: when `UseSystemTextJsonSerializerWithOptions` is set, `fSharpSystemTextJson` if the converter is present and `systemTextJson` otherwise. `CosmosClientOptions` and `CosmosClient.ClientOptions` hand back the very options instance that was set, whose `Converters` hold the `JsonFSharpConverter` with its public `Options` *(verified with SDK 3.62.0 and FSharp.SystemTextJson 1.4.36)*; that property is read first, because with it set `Serializer` is not `null` but the SDK's own `CosmosSystemTextJsonSerializer`, and a client on the SDK default has `null` options and a wrapper of the Newtonsoft serializer *(verified)*; a custom `Serializer` that implements `IJsonSerializerOptionsProvider` (a one-member interface shipped by this package, `abstract Options : JsonSerializerOptions`) → the layout of those options, read from the final instance the serializer holds – this is how the maintainer's own application configures its client (a `CosmosLinqSerializer` subclass assigned to `CosmosClientOptions.Serializer`, never `UseSystemTextJsonSerializerWithOptions`); a `CosmosLinqSerializer` without that interface → names only plus advice `CQ1009`; any other custom serializer or the SDK default (Newtonsoft) serializer → `LayoutRequired` error asking for STJ options or an explicit layout. The explicit route `Translator.Create { … Layout = JsonLayout.fSharpSystemTextJson jsonOptions }` is the primary documented sample. Execution extensions that receive a `Container` and no explicit `Translator` use this (`Translator.OfClient`).

**Defaults.** `Translator.Default` (used when no container is in scope, e.g. `patch { filterPredicate <@ … @> }`) assumes default `JsonFSharpOptions` with default STJ naming and emits advice `CQ1009 LayoutNotConfigured` the first time an optional or union member is translated. Captured values are always encoded by the user's own serializer (parameters), so value encoding is correct under every layout; only member names and null/undefined/tag *paths* depend on the layout.

## 11. Parameterisation, shape key, cache, compiled queries – and the source-generator verdict

**Rule table** (EF funcletizer simplified – F# closures are already leaves *(verified)*): `Value`/`ValueWithName`/`WithValue` → slot named after the captured local (`@minAge`) or `@p<n>`; `PropertyGet (None, moduleValue)`/`FieldGet` → slot (constant only for `[<Literal>]`), so module-level values do not fragment the cache; closed sub-trees with no free query variable (`DateTime.UtcNow.AddDays -1.0`, `Guid.Parse "…"`) → evaluated per `EvaluationPolicy` (`PropertyChains` default: `Value` leaves, static/instance property and field chains, `New*` nodes, `Call` with evaluated arguments, via reflection `GetValue`/`Invoke`; **never `Expression.Compile`**; `LeavesOnly` and `Never` available; markers deny-listed) → slot; `take`/`skip`/`top` operands → slots (`TOP @n` is legal); source-written primitive literals (`p.Age > 18`) → slots by default (`ParameterizeLiterals = true`; stable SQL text for the service plan cache; `InlinePrimitiveLiterals` for readable SQL and golden files); `Query.constant x` forces a literal, `Query.parameter x` forces a slot; identical captured values deduplicate. A `ParameterInliner` pass (EF pattern) turns slots back into literals wherever the backend rejects parameters – `ORDER BY` expressions, `GROUP BY` keys and the `OFFSET`/`LIMIT` of an `ORDER BY RANK` query – and such inlined values are hashed into the shape key. Union tags and object-literal keys are layout facts, always inlined. Never inlining captured values is a correctness decision: the SDK's `SqlQuerySpec` converter routes non-primitive parameter values through `UserSerializer.ToStream(value)` and writes primitives (string/number/bool) directly *(verified in `CosmosSqlQuerySpecJsonConverter`; harmless for the types that matter)*, so `DateTimeOffset`, enums with converters, GeoJSON, options and unions are encoded exactly as stored documents.

**Captured tuples** of either kind are never one slot. A component read arrives as `TupleGet (ValueWithName (t), i)` (over `PropertyGet (None, t)` for a module value) and becomes one typed slot per component, read with `FSharpValue.GetTupleField`/`GetTupleFields` – never with `PreComputeTuplePropertyInfo` or `LeafExpressionConverter`, which throw on `ValueTuple` *(verified in fsi)*. `(a, b) = t` arrives as `Call (op_Equality, [NewTuple …; ValueWithName …])` for both kinds *(verified in fsi)* and is expanded component-wise into `AND`, one slot per component. Ordering between tuples (`<`, `compare`) is `OrderingNotSupported` in 1.0, with the hint to write the lexicographic form or use keyset paging (§9a).

**Shape key.** `Expr.Equals`/`GetHashCode` are unusable *(verified: reference-equal `Var`s, freshly allocated by every `<@ @>` evaluation through `Expr.Deserialize40`)*. One visitor computes node kinds, member keys including generic type arguments (`List.contains<string>` ≠ `<int>`), the type of every tuple node (the two tuple kinds may encode differently, §10), de Bruijn indices for bound variables, typed slot placeholders and the hash of every value that is inlined into SQL text (`Query.constant`, `[<Literal>]`s, `InlinePrimitiveLiterals`, the length of a source-literal `IN` list, `ParameterInliner` results) while extracting slot values; a hit only binds slots. `ConcurrentDictionary<ShapeKey, CompiledPlan>` bounded by `PlanCacheSize` with clear-on-full eviction (simple and tested; LRU later if benchmarks justify) per `Translator`; a `Translator` fixes layout and semantics, so plans never cross configurations. Per-slot `Bind : obj -> ParameterValue` (Marten `ICompiledQueryAwareFilter` idea) lets translators post-process bound values (LIKE escaping, `float32[]` vectors, `GeoShape` → GeoJSON). The cache holds SQL text and slot binders, never a `QueryDefinition`: `QueryDefinition.WithParameter` mutates the instance and returns it, so a shared definition lets concurrent calls overwrite each other's parameters – the defect fixed in 1.2.0 (#32, `getExistsQuery` in `src/Cosmos/Cosmos.fs:208-211`). `ToQueryDefinition` and `CompiledQuery.Definition` build a fresh `QueryDefinition` on every call, and a concurrency test binds different values from parallel tasks and asserts each result.

**Compiled queries.** `CosmosQuery.compile translator <@ fun (args : {| … |}) -> cosmosQuery { … } @>`: the outer lambda's arguments, their record-field accesses and their tuple components (§7) become named slots symbolically (no Marten sentinel trick; booleans work); the quotation is evaluated once at module init, removing the per-call `Expr.Deserialize40` cost; `CompiledQuery<'Args,'T>` exposes `Sql`, `ParameterNames`, `Definition : 'Args -> QueryDefinition`, `Iterator`. `CosmosQuery.ofReflected` resolves a `[<ReflectedDefinition>]` function whose body fsc pickled at build time.

**C# source generator: no.** Roslyn generators and interceptors run only inside C#/VB compilations; fsc has no generator pipeline (fslang-suggestions #864 open since 2020, effort XXXXL; dotnet/fsharp #14300 backlog); a generator referenced from an F# project is silently ignored and can never observe quotations or `[<ReflectedDefinition>]` bodies. EF Core's precompiled queries are C#-only (Roslyn syntax → interceptors) and do not support the Cosmos provider (#33909). Precompilation is a startup feature, not throughput: EF's compiled queries save ~107 µs on a ~670 µs round trip; Marten 9 measured cold 75 ms → 3 ms and steady 710 → 490 µs; our cold cost is a translation of tens–hundreds of µs. The F# strategy that captures the same benefits, in order of value: (1) the shape-key plan cache (translation leaves the hot path; the SDK LINQ provider caches nothing); (2) `CosmosQuery.compile` and `ofReflected` (no `Deserialize40` per call, no `Expression.Compile`); (3) an optional later `FSharp.Azure.Cosmos.Quotations.Build` dotnet tool / MSBuild target after `CoreCompile` that loads the built assembly in an isolated `AssemblyLoadContext`, pre-translates `[<ReflectedDefinition>]`/`[<CosmosQuery>]` members into a manifest keyed by content hash (not metadata token), pre-seeds the cache and fails the build on untranslatable queries – justified only by Phase 0 benchmark numbers; (4) an optional FSharp.Analyzers.SDK "unsupported member" analyzer fed by exported catalog/registry data (FCS version coupling acknowledged). Myriad (untyped AST) and type providers (cannot see the current compilation) do not apply. A C#-consumer companion (Roslyn `SemanticModel` → our SQL AST) is out of scope unless measured demand appears. AOT discipline is kept (no `Expression.Compile`, no LINQ provider, no evaluator libraries at runtime, reflection limited to metadata reads and whitelisted `GetValue`/`Invoke`) but not promised.

A capability probe at `[<AssemblyInitialize>]` issues small queries; `[<RequiresEmulatorFeature>]` tests call `Assert.Inconclusive` when the vNext Linux emulator (CI) lacks the feature (no UDFs – "not planned"; index policies are no-ops, so a missing composite index goes unnoticed *(verified, #44)*; no full text; no spatial functions – one in the projection fails with HTTP 500, "This query type isn't supported yet", and a spatial filter gets an answer without documents, which the SDK cannot read *(verified, #44)*; known `ORDER BY VectorDistance` crash shapes, emulator issue #350). `build.fs` gains an optional `TEST_FILTER` so Windows/macOS jobs can run `Unit|SpecConformance`; a nightly, non-blocking Windows-emulator lane (from Phase 0, maintainer decision) covers spatial/UDF/index behaviour and, behind its own category, the native `QueryPartitionProvider` planner oracle via reflection (Windows x64, brittle across SDK versions, never on the default path).
10. **Plugin conformance kit** (`PluginConformance.run : TranslatorPlugin -> ConformanceReport`): rules resolve to catalog entries, encoders round-trip through `JsonNode` and the emulator accepts the parameter, rules are pure and deterministic, no partial trees, each rule has a golden case; run for every first-party adapter and a fake third-party geometry provider (proves the core has no coupling – Marten's untested `IMemberSource` lesson).
11. **Fakes and plumbing.** `FakeFeedIterator`/`FakeFeedResponse` (moved to shared infrastructure) unit-test execution and `CosmosResponse` mapping without the emulator.
12. **Benchmarks.** Quotation deserialisation, shape-key pass, translation, `QueryDefinition` construction, emulator round trip; numbers gate Phase 5.
13. **Layout conformance** (no emulator, §22.5): the facts the layout reports are asserted against JSON produced by the real serializer, per serializer profile.
14. **Polymorphism** (§21.1): accept and reject lists of discriminators per type, driven by reflection over the registrations.
15. **Corpora.** The ported Marten shapes (§20.14) and the query shapes of the maintainer's Cosmos application (§21.4) run through rungs 1, 3, 5, 6 and the emulator.
16. **No partial translation** (§20.1): mutation tests, conjunct coverage, packs loaded alone, rules never hit.

The infrastructure, data generators, assertion helpers and style of all emulator-backed rungs follow §22.

**Phase 0 result: index usage** *(verified on the Windows emulator)*. A probe script ran the predicates the translator emits over 3000 documents of one logical partition – every tenth without the probed property, every tenth other one with `null` in it – and read the request charge, the retrieved document count of the query metrics and the index metrics. An index seek that returns one document costs 2.92 RU there. The facts stay out of the test suite: request charges are not stable enough to assert, and the vNext emulator of CI reports none and has no index yet but the DiskANN vector index.

- Guards keep the seek: `IS_DEFINED(c.v) AND c.v = @v` costs the 2.92 RU of the bare comparison, the full `Typed` guard `(IS_DEFINED(c.v) AND NOT IS_NULL(c.v)) AND c.v = @v` 3.02 RU, and both read only the matching document through the index `/v/?` (§9, §20.3).
- Equality with an object-valued parameter is a seek as well: `c.o = @o` costs 2.92 RU through the index `/o/?`, `c.o.x = @x AND c.o.y = @y` 3.02 RU, so the advice `CQ1019` is withdrawn (§20.9, §20.15).
- A captured collection keeps the index: `ARRAY_CONTAINS(@values, c.v)` costs what `c.v IN (…)` with the same values costs, 3.05 RU for 2 values and 5.81 RU for 24 (§9, §20.7). `ARRAY_CONTAINS(c.tags, @t)` and `EXISTS(SELECT VALUE t FROM t IN c.tags WHERE t = @t)` are both seeks.
- Arrays of objects lose nothing to `EXISTS`: `EXISTS(SELECT VALUE t FROM t IN c.items WHERE t.name = @n)`, its `JOIN` form and `ARRAY_CONTAINS(c.items, {"name": @n}, true)` all cost 2.92 RU through the index `/items/[]/name/?`, and with a second condition on the same element `EXISTS` costs 3.03 RU and the partial `ARRAY_CONTAINS` 3.02 RU (§9, §20.7).
- A parameter as the ignore-case flag is planned from its value: `STRINGEQUALS(c.s, @s, @f)` and `STARTSWITH(c.s, @s, @f)` cost 2.92 RU with `false`, and `STRINGEQUALS` costs 4.40 RU with `true`, exactly what the literal flags cost (§20.6).
- Ignoring case costs a scan: `STRINGEQUALS(c.s, @s, true)` costs 4.40 RU and `STARTSWITH(c.s, @s, true)` 4.82 RU, the expanded index scan of the indexing overview, although the reference page of `STRINGEQUALS` says that the function performs an index seek; `CONTAINS` and `ENDSWITH`, full index scans, cost 4.12 and 4.11 RU (§20.6).
- `LOWER(c.s) = @s` and `UPPER(c.s) = @s` cost 4.41 RU and read only the matching document, like the case-insensitive `STRINGEQUALS`, although the indexing overview and the query troubleshooting guide call them a full scan that loads every item. `CQ1001` keeps following the documentation, which describes the service (§20.15).

## 17. Risks

- **Serializer mismatch** silently returns no rows → one supported serializer family (STJ + FSharp.SystemTextJson), `ofClientOptions` detection with a `LayoutRequired` error for anything else, per-variant differential runs, `Explain` showing resolved names.
- **SDK-internal Newtonsoft dependency**: dropping the Newtonsoft *layout* does not remove `Newtonsoft.Json` from the process; the SDK may still need it to serialise the query spec → Phase 0 probe, dependency declared by the package if needed. **Materialised in Phase 0** *(verified, §16)*: the `CosmosClient` constructor loads `Newtonsoft.Json` whatever the serializer, and the SDK's build check, which also reaches consumers of packages built on the SDK, asks every consumer to reference it; the Quotations package declares it (§18 item 16).
- **IcedTasks under the Debug regression** (dotnet/fsharp#20466) → Phase 0 probe gates every use; `task` remains the fallback. **Materialised in Phase 0** *(verified, §16)*: in a Debug build, where no resumable state machine is compiled, `cancellableTask`, `cancellableValueTask` and `coldTask` of IcedTasks 0.11.9 share one state machine between all starts of a value, so a second start resumes the first one's suspended state and returns wrong data, and a start that overlaps a suspended one blocks its caller. The defect lies in the dynamic path of IcedTasks, not in this library. Scope: Debug builds only (Release compiles the state machines and passes every probe), those three builders only (`valueTask` and `valueTaskUnit` are not affected), and only a value started more than once – the normal use of a cold or cancellable task value, which is a function meant to be invoked again, for example on retry. Not a misuse of `ValueTask` *(verified)*: Microsoft's rules forbid consuming one `ValueTask` instance more than once (awaiting it twice or concurrently, calling `AsTask` twice, reading `Result` early or twice); the probes call the function value twice and await each returned instance once, the pattern the CA2012 documentation marks as correct, and the defect reproduces with the `Task`-returning `cancellableTask` and `coldTask`, which those rules do not cover. IcedTasks' README lists all three builders as "Multi-start: multiple" ("being able to start the asynchronous code block again") and `CancellableValueTask` separately as "Multiple Awaits: Once"; its static path copies the state machine for every start, while `RunDynamic` creates it once per value outside the start function. The static default-scheduler path of `backgroundCancellableTask` and `backgroundColdTask` lacked the per-start copy too and failed a second start even in Release *(verified upstream)*. **Resolved:** our TheAngryByrd/IcedTasks#67 fixes all of these and is released in IcedTasks 0.11.10-beta001; #40 references it and runs every probe in both configurations with none skipped. Residual risk: the dependency is a prerelease until IcedTasks 0.11.10 is stable (§18 item 15).
- **net10.0-only packages** drop `net8.0` consumers of the existing library → major version bump, stated in CHANGELOG and README.
- **Null/undefined semantics** (SDK #4864 class) → truth table, settled on both emulators by #44 (`??` keeps `null`; comparisons across types are `false` or `undefined`, never true for a missing value), `Typed` guards, interpreter oracle.
- **Normalisation divergence/duplication** → bounded fixpoint with typed errors; idempotence and eval-preservation properties; let-inlining duplication accepted in 1.0, `JOIN (SELECT VALUE e) AS x` hoisting as a later pass.
- **Shape-key bugs** returning the wrong plan → single-pass key with typed slots; properties that distinct queries have distinct keys and alpha-equivalent queries share keys; cache bypass in `Explain`.
- **Plugin ambiguity** (NTS and Spatial both loaded) → build-time conflict detection, `Overrides`, conformance-kit law.
- **Emulator coverage** (vNext: no UDFs, full text or spatial functions, index policies ignored, vector crash shapes) → emulator-free rungs carry most assurance; capability gating keeps CI green; the nightly Windows lane covers what the vNext emulator lacks.
- **Interpreter drift** (OfflineEngine is test-only SDK code) → validated against docs corpus and emulator; deviations documented; hybrid/vector stay on translation-only baselines.
- **Numeric fidelity** (decimal, int64 > 2^53, division by zero, JS-int32 bitwise, Cosmos ticks epoch) → coded warnings, `INTDIV/INTMOD/INTBIT*`, documented policies, edge-value tests.
- **Reflection evaluation** runs user code at translation time and is not AOT-safe → configurable policy, never `Expression.Compile`, deny-list.
- **Scope for a small team** → narrow first slice with a byte-level definition of done; everything else additive through the registry; catalog strictness deferred to Phase 4.
- **Toolchain friction** from the C# grammar project → generated sources checked in, no Java in CI, outside Fantomas, excluded from `dotnet test` by the narrowed glob.
- <del>**Branch in flight**</del>: `origin/copilot/support-throughput-bucket-operation-again` is not needed (maintainer decision 2026-10-02), so Phase 0 starts from `main` and the extraction of `tests/Cosmos.Tests.Infrastructure` has nothing to wait for.
- **Docs strictness** (`fsdocs --strict`) → XML docs on every public member from day one; `.fantomasignore` entries for vendored/generated files. The existing docs have known defects (Getting_Started uses nonexistent `Created`/`Conflict` cases; Background references nonexistent `CancellableTaskSeq.ofAsyncEnumerable`; How_Tos are Rx placeholders) – fix alongside.
- **Hedgehog MSTest adapter** relies on MSTest behaviour the API does not promise – the per-invocation lifecycle of `ITestMethod.InvokeAsync`, the experimental `TestContext.Current` (FS0057 on 4.2.3 and 4.3.2), the per-invocation `[<Timeout>]`, `ITestMethod.MethodInfo.ReflectedType` naming the derived test class of an inherited property, the unpacking of rows into `ITestMethod.Arguments` – and one such behaviour already changed between 4.2.3 and 4.3.2 (a cooperatively timed-out invocation reports `Failed`, then `Timeout` *(verified)*) → the adapter suite pins each behaviour it relies on and runs on every MSTest bump; the adapter stays small and free of repository references, because the same code goes into the upstream pull request and is kept in step with `Hedgehog.NUnit` and `Hedgehog.Xunit`; until upstream merges and publishes it, the in-repository copy is the one the library's tests run.

## 20. Parity with the maintainer's Marten F# layer

Source: the maintainer's earlier F# LINQ layer over Marten (below: the Marten layer; 57 source files) and its test suite (20 test files, 245 test methods). A gap check extracted **489 distinct cases**; a second, independent pass verified every classification against the plan text: **233 covered, 202 partially covered, 28 missing, 26 not applicable** (PostgreSQL/Marten mechanics). The rules below close the partial and missing cases; where they differ from earlier sections they take precedence. SQL shown is illustrative: parenthesisation comes from the printer and key casing from the layout. `h` and `v` denote the has-value flag and the value of an optional pair (§9).

### 20.1 No partial translation

A translator may never drop, weaken or approximate a sub-expression. `NotApplicable` or `Failed` on any node – a conjunct of `&&`, a stage of a collection pipeline, a lambda inside `Option.exists`/`Seq.exists`, a method argument – fails the whole query with a positioned `Unsupported` error. There is no lenient `AND`, no "array is not empty" or "is not null" fallback, and no catch-all exception handler in translation code. This is the dominant bug class of the Marten layer, including a fallback to `IS NOT NULL` that returns documents the predicate should exclude, a data leak. Tests: removing any one registered rule turns every golden case that used it into an error, never into shorter SQL; every conjunct of a generated predicate has a term in the emitted SQL; each built-in pack works when loaded alone; the coverage report lists rules never hit; no test asserts only non-emptiness or a substring.

### 20.2 Normalizer additions

- `etaExpand` applies to the root **and to every function-typed argument of a registered higher-order member**. Operand shapes: lambda; method group (`Option.isSome`); operator section or partial application (`(=) userId`, `(>) 5`, `isOwnedBy userId`); composition whose operands have any of these shapes; first-class operators such as `not`; a function value or a closed call returning a function → `CapturedFunctionValue` unless `[<ReflectedDefinition>]`. The synthesised variable is typed with `FSharpType.GetFunctionElements`, never `obj`.
- Pipes and composition are defined independently of operand shape: `op_PipeRight`/`op_PipeLeft` → `Application (f, x)`; `op_PipeRight2/3` and `op_PipeLeft2/3` → nested applications. Their tuple operand is a reference tuple by the operators' signatures – a struct operand does not compile (FS0001) – and never reaches the normalizer as one value: the compiler passes a syntactic tuple as separate arguments (`Call (op_PipeRight2, [a; b; f])`) and a tuple value `t` as `Let (func, f, Let (arg1, TupleGet (t, 0), Let (arg2, TupleGet (t, 1), Call (op_PipeRight2, [arg1; arg2; func]))))`, with `t` first bound to `tupledArg` when it is not a variable *(verified in fsi)*; `inlineLets` removes these bindings, and the law pair below has no struct twin; `op_ComposeRight [f; g]` → `fun x -> g (f x)`. Operators are matched by FSharp.Core `MethodInfo`, never by name.
- `betaReduce` covers unit thunks (`defaultWith`, `orElseWith`) and curried application; `Coerce (e, seq<_>)` inserted when a collection member is passed to `Seq.*` or LINQ is erased; `a = true` → `a`, `a = false` and `a <> true` → `NOT a`.
- Residual check on application spines: a function-value head with a document-dependent argument → `CapturedFunctionValue` at the outermost application; with closed arguments the whole spine is client-evaluated into one slot.
- Laws with golden pairs: `x |> f a` = `f a x` (the piped value is the last curried argument); `(a, b) ||> f` = `f <|| (a, b)` = `f a b`; `(op) a b` = `a op b`; operator sections preserve operand order (`xs |> Seq.exists ((>) 5)` → `… WHERE (@p0 > t)`); `not << _.IsActive.Value` = `_.IsActive.Value >> not` = `fun d -> not d.IsActive.Value`. Pipes and sections are tested three lambdas deep.

### 20.3 Optional values under comparison

- **Equality on pairs.** `(h1, v1) = (h2, v2)` → `((NOT h1 AND NOT h2) OR (h1 AND h2 AND (v1 = v2)))`. Statically known sides simplify: `= Some e` → `(h AND (v = e))`; `= None` → `NOT h`; `<> Some e` → `(NOT h OR (v != e))`; `<> None`, `not x.IsNone` → `h`. A source-written `Some <expr>` is destructured, never serialised whole. Operands are symmetric.
- **Captured optional values** (`option`, `voption`, `Skippable`, `Nullable`) bind as **two slots** `(@o_has : bool, @o : inner value or null)`: `x = o` → `((NOT @o_has AND NOT h) OR (@o_has AND h AND (v = @o)))`. The SQL text is identical whether the value is `Some` or `None` at run time, a captured `Skip` is expressible, and negation stays correct. This replaces the whole-option parameter of earlier drafts.
- **Ordering of optional values has SQL meaning** (maintainer decision 2026-09-27): `<`, `<=`, `>`, `>=` and `compare` between optional values are true only when both values are present, `a < b` → `(ha AND hb AND (va < vb))`; with a captured optional the has-value slot takes the place of `hb`. Absent values are excluded, as the SDK LINQ provider does today and as the application expects (`token.ExpirationDate < now` must not match a token without an expiration date). This deliberately differs from F#, where `ValueNone < ValueSome x` is true: advice `CQ1021 OptionalOrdering` says so, `Explanations/Null_And_Undefined.md` documents it, and the differential oracle evaluates ordering between optionals with the same rule instead of F# structural comparison. Equality keeps F# meaning (`None = None` is true). Keyset paging (§9a) builds its own predicates and is not affected.
- **Null tests on nullable references.** `isNull p`, `p = null`, `match p with null` → `(NOT IS_DEFINED(p) OR IS_NULL(p))`; the negations → `(IS_DEFINED(p) AND NOT IS_NULL(p))`.
- **NOT-safety invariant.** For every optional predicate `q`, the translation of `not q` is `NOT (translation of q)` and agrees with F# on documents where the member is missing or null.
- **Guard elimination** (`simplify`). `(h AND (v op e))` → `(v op e)` in positive polarity when `e` is a slot or a non-null literal: the Phase 0 table shows that the bare comparison is never true for `null` or `undefined` – equality and `IN` across JSON types are `false`, `null` included, ordering across types is `undefined`, and a missing value makes both `undefined` *(verified on both emulators, #44)*. In negative polarity the guard stays: `NOT (v = e)` is true for `null` but `undefined` for a missing value, so without the guard a negated predicate would lose the documents that lack the member. The guard never costs the index seek – the guarded comparison reads only the matching document, at 3.02 RU where the bare one costs 2.92 *(verified on the Windows emulator, §16)* – so the rule shortens the SQL of the common case `doc.DocumentNumber |> Option.exists (fun n -> n = docNumber)` → `(doc["documentNumber"] = @docNumber)` and saves the guard's small charge.
- **Laws.** `x.IsNone` = `not x.IsSome` = `x = None`; `Option.exists ((=) v) x` = `Option.contains v x` = `x = Some v`; `a <> b` has the row set of `not (a = b)`. Goldens bind the same quotation once with `Some` and once with `None` and assert identical SQL.
- **Migration note.** `= Skip` means *missing only*; the Marten layer treats `Skip` and null alike. `Skippable.toOption x = None` gives the old meaning.

### 20.4 Partial unwraps (`.Value`, `Option.get`, `ValueOption.get`)

- The unwrap reads `v`; member access continues the path at any depth (`d.Submitter.Value.Name` → `inner(d["submitter"])["name"]`), and an optional member there is again a pair. The compiler-generated getters `Value` (option) and `Item` (voption, Skippable) are the same node.
- **Precondition.** F# throws on an absent value, SQL yields `undefined`. Under `Typed` and `Strict` the `h` of the unwrapped value is a precondition of the smallest enclosing boolean atom, hoisted over `NOT` and local to its operand of `AND`/`OR`: `Option.get x > 5` → `(h AND (v > @p0))`; `not d.IsActive.Value` → `(h AND NOT v)`. Documents on which F# would throw are excluded in both polarities. Guard elimination may drop the precondition. `Native` emits the bare `v`.
- **Throwing branches** of an inlined `[<ReflectedDefinition>]` helper (`failwith`, `invalidOp`, `raise`) contribute the negation of their condition as a precondition, so project-level helpers such as a user-defined `Skippable.get` translate without registration.
- **Projections.** The precondition is hoisted into `WHERE` with warning `CQ1012 UnguardedUnwrap`. A top-level scalar projection of the optional value itself (`select p.Nick`) is `SELECT VALUE (h ? v : null)` so the row count is preserved and `None` round-trips; a bare top-level `Skippable` projection is `InvalidQueryShape`. The Marten workaround "select `.Value`, then `Option.ofObj` on the client" is obsolete.

### 20.5 Pair algebra completion

- The default of `defaultValue`/`defaultArg`/`defaultWith` is any scalar expression, also one that reads the document (`doc.Nick |> Option.defaultValue doc.Name`). `defaultWith (fun () -> d)` = `defaultValue d`, `orElseWith` = `orElse`.
- `flatten (h, (h', v'))` → `(h AND h', v')`; `map2 f a b` → `(ha AND hb, f va vb)`; `fold f s` → `(h ? f s v : s)`; unit-returning functions (`iter`) are `Unsupported`.
- **Predicate position.** A bool-typed `(h ? v : d)` is emitted as `((h AND v) OR (NOT h AND d))`, simplified for literal defaults: `defaultValue true` → `(NOT h OR v)`, `defaultValue false` → `(h AND v)`.
- **Optional-typed branches** of `if`/`match` → `((c AND ha) OR (NOT c AND hb), (c ? va : vb))`.
- **Nested optionals.** `Skippable<'T option>`: outer pair `(IS_DEFINED(p), p)`, payload pair `(NOT IS_NULL(p), p)`. `'T option option` under unwrapped encodings is not representable → `AmbiguousNestedOption`.
- Pair rules apply to computed optionals and to paths rooted at any alias (root, JOIN alias, element alias).
- One rule table parameterised by the carrier (`Option`, `ValueOption`, `Skippable`). `Skippable` built-ins are exactly the functions of the package *(verified in the FSharp.SystemTextJson sources)*: `map`, `map2`, `map3`, `bind`, `apply`, `defaultValue`, `defaultWith`, `orElse`, `toOption`, `ofOption`, `toValueOption`, `ofValueOption`, `filter`, `isSkip`, `isInclude`. Functions the package does not define are user code, translated when `[<ReflectedDefinition>]` or registered; members are never matched by simple name.
- Test matrix: optional kind × function × position {predicate, negated predicate, `&&`/`||` operand, comparison left/right/both sides, arithmetic operand, function argument, method receiver, projection, sort key, element predicate}.

### 20.6 Strings

| F# / BCL | SQL |
|---|---|
| `s.Contains x` | `CONTAINS(s, x)` |
| `s.StartsWith x` | `STARTSWITH(s, x)` |
| `s.EndsWith x` | `ENDSWITH(s, x)` |
| `a = b`, `a.Equals b`, `String.Equals (a, b)`, `a.Equals (b, Ordinal)`, `String.Equals (a, b, Ordinal)` | `(a = b)` |
| `a.Equals (b, OrdinalIgnoreCase)`, `String.Equals (a, b, OrdinalIgnoreCase)` | `STRINGEQUALS(a, b, true)` |
| `a.Equals (b, cmp)`, `String.Equals (a, b, cmp)` with a captured `cmp` | `STRINGEQUALS(a, b, @cmp)` |
| `s.Length`, `String.length s` | `LENGTH(s)` |
| `ToLower`/`ToLowerInvariant`/`ToUpper`/`ToUpperInvariant` | `LOWER(s)`/`UPPER(s)` with `CQ1001` |
| `s.[i]`, `s.Chars i` | `SUBSTRING(s, i, 1)` |

**String equality and the `StringComparison` argument** *(quotation shapes verified in fsi; SDK behaviour read from `StringBuiltinFunctions.cs`; index behaviour from the indexing overview on Learn and from the Windows emulator, §16)*.

- **Recognised members**, each by exact `MethodInfo`: instance `Equals (string)`, `Equals (obj)` (the `Box` around a string-typed operand is stripped; any other operand type is `Unsupported`) and `Equals (string, StringComparison)`; static `String.Equals (string, string)` and `String.Equals (string, string, StringComparison)`; `StringComparer.Ordinal`/`OrdinalIgnoreCase`/… `.Equals (a, b)`; `MemoryExtensions.Equals (a.AsSpan (), b.AsSpan (), cmp)`, where `AsSpan ()` of a string is the string itself and `AsSpan (start, length)` is `SUBSTRING`; `String.Compare (a, b, cmp) = 0` and `<> 0`. The instance form arrives as `Call (Some a, Equals, [b; cmp])` and the static form as `Call (None, Equals, [a; b; cmp])`; both build the same scalar tree, so they give byte-equal SQL and share one cached plan. The SDK LINQ provider translates only the instance forms and gives up when the comparison is not a constant.
- **The comparison selects the SQL form; it is never passed through.**
  - *Source literal* (`Value (StringComparison.OrdinalIgnoreCase)`): a translation-time fact, always inlined and hashed into the shape key, never a slot, also under `ParameterizeLiterals = true`. `Ordinal` → `(a = b)`, the same tree as the F# `=` operator, so partition-key lifting, point-read detection and guard elimination see one canonical form of equality. `OrdinalIgnoreCase` → `STRINGEQUALS(a, b, true)`, an expanded index scan by the indexing overview and on the Windows emulator (4.40 RU where `=` costs 2.92, §16) – not the index seek that the reference page of `STRINGEQUALS` states, which holds for the case-sensitive form only. A query that needs the seek compares a lowercase computed property instead (`ComputedProperties`, §21.2), as advisor rule QA1003 recommends.
  - *Captured value* (`ValueWithName (cmp)`, a module value, any closed expression): one boolean slot; the SQL is always `STRINGEQUALS(a, b, @cmp)` and the binder maps the enum value to the flag, so the text never depends on the run-time value. A value outside the enum is `InvalidParameterValue`. Both emulators accept a parameter in this position *(verified, #44)*, so the flag stays a slot and the SQL text does not depend on the comparison; neither does the plan, because the Windows emulator charges a flag parameter exactly what it charges the literal of the same value (§16). A captured comparison never yields the `=` form, so partition-key lifting needs the literal.
  - *Document-dependent expression* (`if p.Strict then Ordinal else cmp`): `Unsupported`, with the hint to branch outside the call.
- **Culture-sensitive values** (`CurrentCulture`, `InvariantCulture` and their `IgnoreCase` variants, the `(string, bool, CultureInfo)` overloads, `StringComparer.InvariantCulture…`): Cosmos compares strings ordinally and has no collation. `Semantics.CultureComparison = Reject | AsOrdinal`, default `Reject`: the error `CultureComparisonNotSupported` names the ordinal replacement, in line with §20.1 (no approximation). `AsOrdinal` maps each value to its ordinal counterpart with warning `CQ1014`, which is what the SDK LINQ provider and the Marten layer do silently. A captured culture value is rejected or mapped at bind time by the same policy. The application uses culture comparisons only in client-side in-memory filters; its one Cosmos query of this kind is ordinal.
- **Operands** are any scalar in either role: member against slot, member against member, slot against member (`"x".Equals (p.Name, OrdinalIgnoreCase)` → `STRINGEQUALS(@p0, p["name"], true)`), the value of an optional pair, a scalar wrapper. Operand order is kept as written. A call with no document-dependent operand (`"djkj".Equals ("dsd", StringComparison.Ordinal)`) is a closed sub-tree: under `EvaluationPolicy.PropertyChains` .NET evaluates it into one boolean slot (`WHERE @p0`), culture-sensitive values included; under `LeavesOnly` or `Never` it is translated like any other call (`(@p0 = @p1)`).
- **Null.** Operands typed `string` are assumed present under `Typed`. For operands typed `string | null` or taken from an optional pair the static forms follow pair equality (§20.3) with the chosen function in place of `=`, because `String.Equals (null, null, cmp)` is true: `((NOT ha AND NOT hb) OR (ha AND hb AND STRINGEQUALS(va, vb, true)))`, simplified when one side is known to be present. In the instance forms the receiver is a partial unwrap (§20.4): `ha` is a precondition and a null argument gives false, `(ha AND hb AND STRINGEQUALS(va, vb, true))`. A captured `string | null` binds as two slots like any captured optional value.
- **Functions without a case flag.** `INDEX_OF`, `REPLACE` and the ordering operators have none: `IndexOf`/`Replace` with `OrdinalIgnoreCase` and case-insensitive ordering (`String.Compare (a, b, OrdinalIgnoreCase) < 0`) are `Unsupported`; the hint shows the `ToLowerInvariant` spelling, which is a scan.
- **Required consumer shape** (a prefix-existence check of the maintainer's application): `p.PrefixNormalized.Equals (query.Prefix, StringComparison.OrdinalIgnoreCase)` → `STRINGEQUALS(p["prefix_normalized"], @p0, true)`.
- **Probes and tests.** Phase 0 results *(verified, #44)*: a parameter works as the third argument and a bare boolean parameter as the whole predicate (`WHERE @p0`); `STRINGEQUALS` is `undefined` unless both operands are strings, so over `null`, a missing value or a number it drops the row in either polarity; the ignore-case flag folds some non-ASCII letters otherwise than .NET `OrdinalIgnoreCase` – on the Windows emulator only the Greek final sigma (`ς` against `Σ`: not equal, while .NET calls them equal), on the vNext emulator also the dotted capital I, the Kelvin sign and the Angstrom sign, which it equates with the letters they lowercase to. The divergence depends on the engine and is reported as advice `CQ1022 CaseFoldingFidelity`. Truth table as data-driven cases: six comparison values × {instance, static, `StringComparer`, span} × {literal, captured} × {member–slot, member–member, slot–member, closed} × {predicate, negated, inside `Option.exists`, projection}. Laws: instance and static forms give byte-equal SQL; every `Ordinal` form is byte-equal to `a = b`; literal and captured comparison return the same rows.

**Other string functions.** Overloads of `Contains`/`StartsWith`/`EndsWith`: `string`, `char`, `(string, StringComparison)`, `(string, bool, CultureInfo)`. The comparison argument follows the rules above, except that `Ordinal` gives the two-argument form of the function; a captured comparison binds the third argument as a boolean slot, which both emulators accept *(verified, #44)*. Receiver and argument are any scalar, including the value of an optional pair and another member. `LIKE` is never generated for these functions, so `%` and `_` in user input need no escaping (the Marten layer builds unescaped `LIKE` patterns). `string` is never a collection: `Seq.*`/`Enumerable.*` applied to a string are `Unsupported`; string `Contains` and collection `Contains` are told apart by declaring type.

### 20.7 Collections

- **Keyed by operation, not by collection type.** Any member whose `CollectionEncoding` is a JSON array is a path, and every member family maps `contains`, `exists`/`Any`, `forall`/`All`/`TrueForAll`, `filter`/`where`/`Where`, `map`/`Select`, `length`/`count`/`Length`/`Count`, `isEmpty`/`IsEmpty`/`IsDefaultOrEmpty` and the indexer to the same SQL forms. Families: FSharp.Core `List`, `Array`, `Seq`, `Set`; FSharp.Collections.Immutable modules (compiled names `ImmutableArrayModule`, `ImmutableListModule`, `ImmutableHashSetModule`, `ImmutableSortedSetModule`, recognised by declaring-type full name); `System.Linq.Enumerable` **and `System.Linq.ImmutableArrayExtensions`** (the overloads F# binds for `ImmutableArray` receivers – missing them was a production bug of the Marten layer) and `MemoryExtensions`; BCL instance members; interface members through a pattern translator keyed on `IEnumerable<'T>` plus JSON-array encoding, so set and list types of other libraries (FSharp.HashCollections) work without a plugin. Each key carries an argument-role map (collection, element, predicate) because F# modules and LINQ use opposite argument orders. The element type comes from `IEnumerable<'T>` of the **static** type.
- **Captured collections.** Direction is decided by free-variable analysis, not by module: closed collection and document-dependent element → `ARRAY_CONTAINS(@xs, <e>)`, which the Windows emulator serves from the index at the cost of the equivalent `IN` (§16); document path → `ARRAY_CONTAINS(<xs>, <e or @e>)`; both closed → client-evaluated bool slot. Any closed `IEnumerable<'T>` is one JSON-array slot, enumerated exactly once at bind time, each element encoded with the static element type, so the element JSON equals the JSON stored for a member of the same CLR type. The shape key uses the element type, not the concrete collection type.
- **Empty and null.** A captured empty collection keeps the SQL text; a source-literal empty list folds to `false`. A null captured collection is the bind-time error `InvalidParameterValue`. `None` is never replaced by `default('T)`: `values |> List.contains p.X` with optional elements binds `(@hasNone, @somes)`.
- **Pipeline fusion** (new pass `fuseCollectionPipelines`): `exists q (filter p xs)` → `exists (fun t -> p t && q t) xs`; `isEmpty (filter p xs)` → `not (exists p xs)`; `contains v (map h xs)` → `exists (fun t -> h t = v) xs`. One subquery per pipeline: `xs |> Seq.where p1 |> Seq.where p2 |> Seq.exists q` → `EXISTS(SELECT VALUE a FROM a IN doc["approvals"] WHERE ((p1 AND p2) AND q))`.
- **Same-element semantics.** All conjuncts are evaluated on one element. `ARRAY_CONTAINS(arr, {...}, true)` is used only for one conjunction of equalities packed into one partial object, opt-in through `PreferArrayContains`, which shortens the SQL and gains no index use: both forms are seeks (§16). The Marten translation lets different elements satisfy different conjuncts.
- **Element equality.** `exists (fun t -> t = e)`, `exists ((=) e)` → `ARRAY_CONTAINS(xs, e)`; `forall (fun t -> t <> e)` → `(NOT ARRAY_CONTAINS(xs, e))`.
- **Negation and correlation.** `not (xs |> Seq.exists p)` → `(NOT EXISTS(...))`, true over a missing array as F# `forall` over an empty collection. Element predicates may reference outer aliases; the query variables are the root alias plus every enclosing element-lambda variable.
- **Emptiness on members that may be absent.** `isEmpty` → `(NOT IS_ARRAY(x) OR (ARRAY_LENGTH(x) = 0))`, `length` → `(IS_ARRAY(x) ? ARRAY_LENGTH(x) : 0)`.
- **Option-returning functions.** `tryHead xs` → pair `((ARRAY_LENGTH(xs) > 0), xs[0])`; `tryItem`; `tryFind`/`tryPick`/`tryLast` are `Unsupported` until the subquery probes allow them. `Set.isSubset`/`isSuperset` → `ARRAY_CONTAINS_ALL`.
- **Named goldens** are the maintainer's production shapes, for example the "action required" predicate over `doc.Approvals` with `Seq.where`, `ValueOption.exists` and `not (… Seq.exists (fun a -> a.Status <> Approved))`.

### 20.8 Scalar wrappers and transparent members

- **Detection is structural**, with no whitelist: a type is a scalar wrapper when it is a union with exactly one case and one field, including private or internal cases, struct unions and closed generic instantiations with phantom arguments (`TypedGuid<'P>`, `TypedString<'P>`). Classes or structs with a custom converter register `TypeMapping.scalarWrapper`. The Marten layer uses a closed whitelist of six generic definitions and needs edits in four places for every new wrapper kind.
- **Derived mapping.** `JsonType`, `IsOrderable`, `ToLiteral` and the numeric/date warnings are those of the innermost field type; nested wrappers compose.
- **Values** are always one parameter serialised by the user's serializer. A captured value without a `TypeMapping` is still bound; `NoTypeMapping` arises only when a literal is required.
- **Operators.** `=`, `<>` compare the path with the parameter; `<`, `<=`, `>`, `>=`, `compare`, `CompareTo` are the same operator on the inner path when `IsOrderable`, otherwise `OrderingNotSupported`.
- **Sort and group keys.** `sortBy d.Name`, `sortBy d.Name.Value`, `sortBy (TypedString.value d.Name)` → `ORDER BY d["name"]`; wrapper accessors never trigger `OrderByNotPath`.
- **Transparent members.** `TypeMapping.Members : ImmutableArray<struct (MemberKey * MemberProjection)>`, `MemberProjection = Identity | Path | Sql | Unsupported`. `Identity` is the path of the owner itself: `MailAddress.Address`, `Uri.OriginalString`, wrapper `.Value`/`Item`, module accessors such as `TypedGuid.value`, `op_Implicit`. A member that is not listed is `Unsupported`; it is never a nested path and never silently the scalar (the Marten check ignores which member is accessed, so `e.Host` would compare the whole address). Accessors are recognised when compiler-generated, `[<ReflectedDefinition>]`, marked `[<CosmosUnwrap>]`/`[<CosmosWrap>]`, or listed.
- **Type-owned hooks.** `TypeMapping.Equality` and `TypeMapping.Containment` let a type own `=`, `<>`, ordering and "member in captured collection". `StoredShape` declares the stored JSON of a type whose converter hides it.
- Provider resolution is by specificity (exact type, generic definition, pattern) and only then by registration order; shadowed providers are reported. Registration order is never load-bearing.

### 20.9 Unions

SQL text depends on the static shape of the expression only, never on the run-time case of a captured value.

- **Fieldless source literal.** `x.Status = Pending` is normalised to `UnionCaseTest`: identical SQL to `x.Status.IsPending` and to `match`. Tag test per layout: adjacent or internal tag → `(x["status"]["Case"] = "Pending")`; bare string → `(x["status"] = "Pending")`; external tag → `IS_DEFINED(x["status"]["Pending"])`. The tag value is the case's `JsonName` when present.
- **Enum-like unions, captured value or collection.** `x.Status = status` → `(tagPath = @status)`; `statuses |> List.contains x.Status` → `ARRAY_CONTAINS(@statuses, tagPath)`; the slot binder extracts the layout tag names.
- **Unions with fields.** A captured value or a closed case with fields is **deep equality on the whole value** `(p = @p0)`, serialised with the slot's static type, which the Windows emulator serves as an index seek (§16). Object equality ignores the order of properties and array equality does not *(verified on both emulators, #44)*, so the property order of the parameter does not matter while a list field keeps the order semantics of F#. When a field depends on the document → `(tagTest AND (fieldPath = e) …)`. Tag-only comparison must be asked for explicitly (`u.IsC`, `match`, `Cosmos.Functions.sameCase`). The Marten layer compares case names only, so `Rejected "a"` equals `Rejected "b"`.
- **Inequality.** Case with fields → `(NOT tagTest OR (fieldPath != @x))`, so documents of other cases are included.
- **Ordering** on a multi-case union → `OrderingNotSupported` (F# orders by tag index, JSON stores case names).
- **Null.** A captured union that is null at bind time is that case only when the type uses `UseNullAsTrueValue`; otherwise `InvalidParameterValue`. Deliberate non-parity with the Marten layer, which reads null as the default case.
- **Layout model.** `UnionLayout` = tag placement × field layout (§10), total over union types found with non-public binding flags, resolved recursively. Field paths: `Positional` → `p["Fields"][i]`; `Named` → `p["Fields"]["<name>"]` (a single unnamed field is `"Item"`); `UnwrappedSingleField` → `p["Fields"]`. The adapter maps every `JsonUnionEncoding` flag. **Legacy read encodings**: `JsonLayout.withLegacyUnionEncoding` adds a read encoding; tag tests become an OR over the encodings with advice `CQ1015 MixedEncodingScan` – the Marten data exists in two encodings at once.

### 20.10 Entry points and API surface

- The functional `Query` module is complete (§15), mirrors the Marten `Queryable` module (24 functions) and keeps compile-time ordering state through `OrderedCosmosQuery<'T>`. Migration table: `filter` → `where`, `map` → `select`, `orderBy` → `sortBy`.
- `Query.groupBy` must be followed by `Query.select` over the group; `where` over the result of that `select` lowers to a filter outside a `GROUP BY` subquery, `SELECT VALUE x … FROM (SELECT … GROUP BY …) AS x WHERE …`, which stands in for the missing `HAVING` *(verified on both emulators, #44)*; a sort by an aggregate of the group is `OrderByNotPath`, because an `ORDER BY` outside a subquery accepts only paths of the documents (error 2206, verified). `Group<'K,'T>` accepts the property spelling (`g.Count`) and the LINQ spelling (`g.Count ()`, `g.Sum (fun x -> …)`).
- Terminals (§15): throwing and try forms of first and exactly-one, 32- and 64-bit counts, predicate counts, continuation-token page, page-number page with total, keyset page. Try-terminals carry no `not struct`/`not null` constraint: emptiness is decided from the feed response item count, never from a null or default check (the Marten terminals use null as the "no result" signal and are restricted to reference types). Curried token-first pipeline terminals (`|> Query.countAsync ct container`) mirror the Marten module and return the same types as the `Container` members (the continuation-token page is `struct {| Items : ImmutableArray<'T>; ContinuationToken : string voption |}`, never a tuple); the tupled `Container` members stay the primary documented surface.
- **Programmatic quotations.** The translator accepts any well-typed `Expr`, including trees built with `Expr.Lambda`, `Expr.PropertyGet`, `Expr.Call`; the shape key is structural. `Field.ofName`, `Query.whereExpr` and `SortKey` values serve filters and sort fields that arrive at run time. A how-to shows an adapter for the FSharp.Data.GraphQL `ObjectListFilter`, which the application applies to its queries today.
- **Delegate-rooted quotations.** `<@ Func<'T, bool> (fun x -> …) @>`, the shape the application uses for expressions that are also lowered with `LeafExpressionConverter`, is accepted by `Query.where` and the `Predicate` combinators; `normalizeDelegates` turns the root into a lambda. The struct preference does not extend to such shared expressions: `LeafExpressionConverter.QuotationToLambdaExpression` throws `ArgumentException` on any `TupleGet` over a struct tuple – the shape of every struct destructuring – and `NotSupportedException` on member access to a struct anonymous record, while struct tuple construction converts *(verified in fsi, FSharp.Core 10.1.401)*; expressions that are also lowered that way keep the reference forms.
- **Module-level queries.** `CosmosQuery` values and results of `CosmosQuery.compile` are evaluated by the static initialiser of their file; a value that refers to a value declared later in the same file fails at initialisation and breaks every static value of that file. `CompiledQuery` therefore translates lazily on first use, and the documentation tells users to declare fragments before the queries that splice them.
- **Telemetry.** Parameterised query text contains no values. `Inline` print mode and `InlinePrimitiveLiterals` put values into the trace attribute `db.query.text`; both stay opt-in.

### 20.11 Booleans, comparison functions, struct projections

- `<>` on non-optional members → `(a != b)`; under `Strict` → `(NOT IS_DEFINED(a) OR (a != b))`. The translator never rewrites `<>` into `NOT (=)`: they differ on undefined.
- `a.Equals b`, `Object.Equals`, `IEquatable.Equals`, `String.Equals (a, b)` translate as `a = b`; `compare a b op 0`, `a.CompareTo b op 0`, `String.Compare`/`CompareOrdinal (a, b) op 0` are rewritten to `a op b`. For `string` operands `a.CompareTo b`, `String.Compare (a, b)` and `String.Compare (a, b, ignoreCase)` are culture-sensitive in .NET, while F# `compare` and the comparison operators are ordinal, so the former follow the culture policy of §20.6; `String.CompareOrdinal` and `String.Compare (a, b, StringComparison.Ordinal)` always translate. A static `op_*` comparison operator declared on any type is translated when the operand type's mapping is scalar (equality) and orderable (ordering).
- **Ordering fidelity.** `Guid` compares in Cosmos as its lower-case string, which differs from `Guid.CompareTo`; strings compare ordinally. `IsOrderable` is true for `Guid` only together with warning `CQ1018 OrderingFidelity`.
- **Struct tuples are the documented tuple forms** (maintainer decision 2026-09-27, §4): `select struct (a, b)` for positional projections (an anonymous struct record `select struct {| … |}` instead of a tuple where names are wanted); `groupBy (struct (p.City, p.Country)) into g` for a multi-member group key (`GROUP BY p["city"], p["country"]`; components read with `let struct (city, country) = g.Key`; a projected `g.Key` is materialised through `TupleEncoding`); `sortBy (struct (p.Name, p.Age))` for a tuple sort key (§9); struct tuples as the keyset `'Key` (§9a); `fun (struct (a, b)) -> …`, `let struct (a, b) = …` and `match … with struct (…)` for destructuring. The how-tos and `Reference/Construct_Mapping.md` show these first.
- **Reference forms stay accepted** because users write both, and a selector whose result type is generic (`Query.groupBy : Expr<'T -> 'K>`, a CE operation typed `'T -> 'R`) turns a plain `(a, b)` into a reference tuple *(verified in fsi)*. Both kinds arrive as the same `NewTuple`/`TupleGet` nodes, told apart only by `Expr.Type` *(verified in fsi)*, and translate to byte-equal SQL – the tuple-kind law of §7 with a golden twin per case (§13) – except where a tuple is materialised into JSON and `TupleEncoding` (§10) answers differently for the two CLR types (plain STJ without `IncludeFields`, a converter for one of them); there one twin is refused. Struct anonymous records and `[<Struct>]` records translate exactly like their reference counterparts; member access on a struct anonymous record goes through `eraseStructReceivers` (§7). No API overloads a generic selector with a struct-typed one (`Expr<'T -> 'K>` next to `Expr<'T -> struct ('A * 'B)>`): a plain `(a, b)` silently picks the generic overload and `struct (a, b)` becomes ambiguous (FS0041) *(verified in fsi)*.
- Object keys are emitted in the target type's field order: declaration order for records and classes; for anonymous records of either kind the order of the compiled type, which sorts the field names ordinally (uppercase before lowercase: `{| b = 1; A = 2 |}` gives `A, b`, `{| a = 1; B = 2 |}` gives `B, a`), the order both serializers write *(verified in fsi)*; the source order survives only as partial evaluation-order `Let` hoisting, skipped for variable values *(verified in fsi)*.
- **Struct values the compiler rejects in quotations** *(verified in fsi, F# 10 / SDK 10.0.401)*. Member access on a captured local of a value type is compile error FS3155 ("A quotation may not involve an assignment to or taking the address of a captured local variable"): `args.MinAge` on a captured `struct {| … |}`, `s.X` on a captured `[<Struct>]` record, and equally `v.IsSome`/`v.Value` on a captured `voption`, `d.Year` on a captured `DateTime`, `kv.Key`, `g.ToString ()`. Member access on a struct anonymous record stored in a record field (`p.Anon.A`) is FS0450 ("Quotations cannot contain expressions that take the address of a field"). Struct tuples are not affected: a captured struct tuple is destructured as `TupleGet (ValueWithName (t), i)`, and a method call on one goes through `copyOfStruct`. Where the documentation uses struct anonymous records or `[<Struct>]` records, it shows them as lambda parameters (compiled-query arguments), quotation-local values and projection results, and tells users to read members of captured struct values outside the quotation (`let minAge = args.MinAge`), to rebind them inside it (`let a = args in a.MinAge`), or to use module functions (`ValueOption.isSome v`, `match v with ValueSome x -> …`); all of these compile. Reference anonymous records and `option` members are unaffected.

### 20.12 Serializer facts read by the layout

- **Optional guards** are narrowed to `AlwaysUndefined`/`AlwaysNull` only with `NarrowOptionalGuards = true` and, for `SkippableOptionFields.Always`, only when `deserializeNullAsNone` is false. The maintainer's containers hold documents written by more than one serializer configuration, and hand-written or legacy documents contain explicit nulls.
- `AllowNullFields = true` → advice `CQ1017 NullableFieldsAllowed`; `Semantics.NullByType` lets only legacy types pay for guards.
- `MapEncoding`: object → `m.[k]` is `c["m"][@k]` *(a parameter as indexer: verified on both emulators, #44)*, `ContainsKey` → `IS_DEFINED`; keys are rendered through the key converter's property-name form.
- `EnumEncoding` is `String` when a `JsonStringEnumConverter` applies.
- **Unknown converters.** The effective converter per type is resolved with `options.GetConverter` (first match wins, as in STJ). A converter not known to the layout makes the value *opaque*: whole-value comparison with a parameter is allowed, member access inside it is `LayoutRequired` with advice `CQ1016 CustomConverterUnknownShape`, unless a `TypeMapping`, a `StoredShape` or an override is registered. This also covers F# records claimed by a user converter registered before `JsonFSharpConverter`.
- Fields are serialised only with `IncludeFields` or `JsonInclude`.
- NodaTime values work as parameters through the user's converter; member calls need the optional plugin.

### 20.13 Query scope and write-side helpers

- **Scope.** `QueryScope = { PartitionKey; Filter per type }` is a plain value passed to the execution extensions or carried by a thin `ScopedContainer` wrapper, applied to every query unless the query calls `withPartitionKey` or `crossPartition`. It replaces the ambient tenant of the Marten sessions and serves soft-delete filters as well. Advice `CQ1013 CrossPartitionQuery` when no key can be derived.
- **Partition-key merge rule.** A partition key already present in the caller's `QueryRequestOptions` wins over lifted keys and `withPartitionKey` hints; lifting with hierarchical paths yields a full key when all levels are equality-constrained and a prefix key when only the leading levels are.
- **Ids and partition keys.** A Cosmos `id` is a JSON string: numeric and wrapper ids are converted to the string the serializer writes; partition-key values must map to string, number, bool or null.
- **Write-side helpers** are client-side composites, not write statements: `Translator.PatchPath : Expr<'T -> 'V> -> string` resolves a member chain into a JSON Pointer (`/address/city`) – the application hand-rolls this today; `Patch.set`/`add`/`replace`/`remove`/`increment` take the selector quotation; `DeleteWhereAsync` and `PatchWhereAsync` query ids, partition keys and `_etag` into a `[<Struct>]` row record with fixed JSON names (a struct tuple row would depend on `TupleEncoding` – a JSON array under FSharp.SystemTextJson, `{"Item1": …}` under plain STJ only with `IncludeFields`, and no readable form otherwise, because plain STJ throws on an array and fills defaults from an object *(verified)*), then write per item or per `TransactionalBatch`, documented as not atomic across partitions; their result is an anonymous struct record.
- A user-facing in-memory runner `CosmosQuery.runInMemory` in the `.Testing` package replaces the dual code path the Marten paging code needs for in-memory providers.

### 20.16 Lessons from the Marten layer that the design respects

Never degrade silently and never swallow failures (`try/with` plus `Debug.Assert`, `Debugger.Break` in library code). Translation is position-independent: one scalar translator for every clause, with a test per context. Optional values are composable pairs, not per-comparison rewrites (the Marten layer needs 36 marker methods and hand-codes nesting for exactly one and two levels). Guards of `exists`-style functions stay inside a negation, preconditions of partial unwraps stay outside. SQL text never depends on run-time values. Members are matched by exact identity while whole overload families are registered. Normalisation happens once, at quotation level, in one bounded fixpoint that revisits children. Absent values are never mapped to `default(inner)`. Layout facts come from one layout service derived from the real serializer options, never from flags passed by hand. Process-wide caches that ignore configuration are avoided. Element types come from static types. Null ordering and paging rules are re-derived for Cosmos, not copied from PostgreSQL. All entry points share one normalizer. Weak tests hide wrong translations.

### 21.1 Type discriminators for heterogeneous containers

- Documents of several types share a container and are distinguished by System.Text.Json polymorphism: `JsonDerivedType (derivedType, discriminator)` on abstract bases, JSON property `$type`. Values are versioned, `<kind>+v<n>` (`order+v1`, `vehicle-electric-car+v1`). Queries never compare the full value: they test a **prefix without the version** (`order+`) or a family prefix (`vehicle-electric`, `vehicle`), so every schema version and every family member matches. The trailing `+` separates `item+` from `item-group+`.
- Today every persisted type carries a hand-written static discriminator expression, and bases enumerate an OR-chain of `StartsWith` calls by hand.
- **Design.** `IJsonLayout.Polymorphism` reads the discriminator property name and the registered `(derived type, discriminator)` pairs from `JsonPolymorphic`/`JsonDerivedType` (attribute subclasses included) and from FSharp.SystemTextJson internal tags. `DiscriminatorOptions.Match = Exact | Prefix of separator : string` (the application uses `Prefix "+"`). `items<'T>` for a type in a polymorphic hierarchy adds the filter for `'T` and its registered descendants, collapsing to the shortest common prefixes: `STARTSWITH(c["$type"], "order+")`, or an OR of prefixes for a base type. `:? Derived` inside a predicate, `Query.ofType<'Derived>` and `Predicate.ofDerived` lower to the same test. The filter is overridable per type (`DiscriminatorOptions.Overrides : Type -> Expr`), because lookup documents filter on a type property of their own, not on `$type`.
- **Automatic filter behind a translator option** (maintainer decision 2026-09-27). `DiscriminatorOptions.AutoFilter : bool`, default `false`. When `true`, `items<'T>` and `Query.source<'T>` add the filter for every type of a polymorphic hierarchy, and `Query.withoutTypeFilter` opts one query out. When `false`, the filter appears only where it is asked for: `Query.ofType`, a `:?` test, `Predicate.ofDerived`. The option is part of the translator, so it is part of the plan-cache identity, and `Translator.Explain` shows whether a filter was added and for which types.
- **Details.** The application has no `[<JsonPolymorphic>]` attribute; `$type` is the System.Text.Json default name. `JsonDerivedType` attributes are repeated on intermediate bases and on the derived class itself, so discovery de-duplicates. A base type yields the OR of the per-type prefixes of its registered descendants; prefixes are not collapsed to a common prefix automatically, because a shorter prefix may match a type outside the hierarchy (`item+` against `item-group+`); family prefixes such as `vehicle-electric` are declared through `Overrides`. Both prefix tests and exact equality on the discriminator are required shapes. Discriminator constants are `[<Literal>]` values, so they arrive in quotations as constants and are inlined; golden cases fix that form. Old schema versions stay in containers, so test data holds documents of two versions under one prefix, and the polymorphism rung has an accept list and a reject list per type.
- `c["$type"]` needs bracket notation, which the printer always uses.
- Test rung: for a hierarchy with `JsonDerivedType` registrations, the generated filter of every base type accepts every registered discriminator under it and rejects the others, driven by reflection, so a newly registered type cannot be silently missed.

### 21.2 Members that the serializer ignores but queries use

- The application marks query-only members `[<JsonIgnore>]`: the discriminator (`[<JsonPropertyName("$type"); JsonIgnore>]`), normalised members that are container computed properties (`EmailNormalized`, `NameNormalized`, `PrefixNormalized`), and wrapper properties over nullable backing fields (`token.Subject` over `val mutable subject : string | null`). Its own `SerializeMemberName` ignores `JsonIgnore` completely.
- **Design** (maintainer decision 2026-09-27). Addressable in a query is not the same as written by the serializer. A member is addressable when it carries `JsonPropertyName`, has `JsonIgnore(Condition = WhenWriting | WhenWritingNull | WhenWritingDefault)`, is mapped through `[<CosmosPath "name">]` or `TranslatorOptions.MemberPaths`, or is a registered computed property. A member with a plain `[<JsonIgnore>]` and none of these is the error `MemberNotSerialized`, whose hint names the two ways to declare the path. This protects against queries over a property that is not in the document, which return nothing without any error.
- **Migration cost for the application.** Its most frequent wrapper members (`token.Subject`, `FirstName`, `LastName`, `Payload`, `ReferenceId`) are unconditional `JsonIgnore` wrappers without `JsonPropertyName`; they work today only because the policy name of the wrapper equals the policy name of the backing field. Each needs one `[<CosmosPath>]` attribute or one `MemberPaths` entry.
- **Computed properties** apply in `WHERE`, `SELECT` and `ORDER BY`: a model member that *is* the computed property translates to its path, and `p.Name.ToLower ()` may be rewritten to `c["name_normalized"]` when `ComputedProperties` maps the expression, which also removes `CQ1001`.
- **Wrapper getters change meaning.** `Subject` returns `""` when the stored member is absent, so F# `token.Subject = ""` is true for a document without `subject` while SQL `c["subject"] = ""` is not. `TranslatorOptions.MemberDefaults` (or `[<CosmosDefault>]`) marks a non-optional member as possibly absent with a default, translated as `(IS_DEFINED(p) ? p : @default)`. The same switch covers optional-with-default members that are not option-typed (empty string, `0`, enum default).
- Member-level `JsonIgnore(Condition = WhenWritingNull | WhenWritingDefault)` on class properties and fields decides the absence encoding of that member, next to `SkippableOptionFields`.

### 21.3 Document and naming shapes

- Document types are **classes**: constructor parameters for required values, settable auto-properties for optional ones, public or internal mutable fields with `JsonInclude`, abstract and overridden properties, inheritance. Member-name resolution looks at the declaring type of an inherited or overridden property. Projection into a class (`NewObject` followed by property setters) is defined like a record projection.
- Naming policy is `SnakeCaseLower` for Cosmos, set after a shared configuration that sets camelCase: names are resolved through `options.PropertyNamingPolicy.ConvertName` of the **final** options instance, never a hard-coded routine. `JsonPropertyName` takes precedence.
- A `JsonExtensionData` dictionary holds unknown properties: `e.Properties["k"]` translates to the **root** path `e["k"]`, not `e["properties"]["k"]`.
- The production `JsonFSharpOptions` are `InternalTag | AllowUnorderedTag | NamedFields | UnwrapSingleCaseUnions | UnwrapRecordCases | UnwrapOption | UnwrapFieldlessTags` with tag name `$type`, `SkippableOptionFields.Always` with `deserializeNullAsNone`, `MapFormat.Object`, string enums. This exact combination is a named, mandatory variant of the test matrix ("maintainer production profile").
- Converter-backed types (id wrappers serialised as string or number, sets as arrays, `Claim` as object, `Uri`, `MailAddress`) are opaque scalars (§20.12).
- Map members are JSON objects: `user.ScopeRoles.Values.Contains roleId`, `Map.exists`, `Map.containsKey` lower through `ObjectToArray` into `EXISTS(SELECT VALUE kv FROM kv IN (SELECT VALUE ObjectToArray(c["m"])) WHERE (kv["v"] = @p))`, and `ARRAY_CONTAINS(ObjectToArray(c["m"]), {"v": 2}, true)` finds a value as well: the source of `IN` must be a path or a subquery, so the direct form `kv IN ObjectToArray(c["m"])` is a syntax error (SC1001) *(verified on both emulators, #44)*. The application uses a UDF for this today with the comment "TODO: Use LINQ". The pair forms reach the translator as forced reference tuples (§4) and read the same element: `Map.toSeq`/`Map.toList` elements destructured with `fun (k, v) -> …` (`TupleGet (tupledArg, i)`) and the `KeyValue` pattern (`TupleGet (Call (KeyValuePattern, [kv]), i)`) *(verified in fsi)* lower like `kv.Key`/`kv.Value` to `kv["k"]`/`kv["v"]`.
- STJ writes `DateTimeOffset` with `+00:00` and `DateTime (Utc)` with `Z` and drops trailing zero fractions, so the two types do not give comparable strings. F# comparison operators need equal operand types, so such a predicate cannot be written with operators; this stays a Phase 0 probe and a documentation note.
- Partition-key members carry `[<JsonPropertyName(PartitionKeys.LevelN)>]`; the same name declared twice in a hierarchy throws in System.Text.Json, so the layout resolves names on overridden members through the declaring type.
- Members typed `string | null` raise nullness warning 3261 inside quoted lambdas; the application brackets such quotations with `#nowarn 3261`/`#warnon 3261`. The library's samples and tests follow the repository rule (smallest possible scope, never file-wide).

### 21.4 Query shapes in use

Equality and AND chains on strings, Guids and wrappers; `<>` against union-case literals; `OR`; `DateTime <`; optional equality with `ValueNone`/`ValueSome`; `Equals (x, OrdinalIgnoreCase)`; `StartsWith`; nested paths; enum equality; collection `Contains` in four forms (member array contains captured scalar, captured sequence contains member, member array of non-primitive elements, third-party set type); UDF invocation; scalar and multi-member projections (the latter delegated to C# helpers today because of dotnet/fsharp#3782, which a quotation translator removes); single and multi-key ordering including `_ts` and computed properties; `CountAsync` and raw `SELECT VALUE COUNT(1)`; conditional predicate composition with `ValueOption.foldBack` chains of `Where`; hierarchical partition keys with prefix keys and explicit null or none components, always passed through request options; nested query wrapping `SELECT VALUE root FROM (<query>) AS root <condition>`, which makes the FROM-subquery probe a requirement of a real consumer.

The raw SQL strings of the application (`SELECT VALUE COUNT(1) FROM a WHERE STARTSWITH(a["$type"], @Type)`, `SELECT * FROM c where udf.IsUserInRole(c, @roleId)` and others) join the result-equivalence list of Phase 1 and 2.

### 21.5 Coexistence with the SDK LINQ provider

Three OpenIddict store methods accept caller-supplied `Func<IQueryable<T>, IQueryable<R>>` because the OpenIddict interfaces require it. They cannot move to quotations, so the application keeps the SDK LINQ provider for them and the existing `IQueryable` helpers of `FSharp.Azure.Cosmos` stay.

### 21.6 No golden SQL exists in the application

None of the 16 LINQ test methods asserts SQL text: each writes `QueryText` to the test log, and most have no assertion at all. There are no expected strings to reuse. If application shapes are wanted as reference output, a Phase 0 task runs those tests and captures the logged text; it is reference for result equivalence only, since the SDK inlines captured values and uses the alias `root`.

## 22. Database test architecture (the maintainer's conventions)

The application's conventions are adopted where they apply to a library and adapted where a library with thousands of translation cases needs something else. Since #39 the shared project `tests/Cosmos.Tests.Infrastructure` holds the pattern with the partition budget (§22.4), name sanitising and the class-level identifier (§22.3), and the leftover sweep by age; the STJ serializer configuration and deep comparison (§22.5, §22.7) come with the first test project that needs them.

### 22.1 Projects and runner

- Test projects are executables on the MSTest runner: `OutputType=Exe`, `EnableMSTestRunner=true`, `IsTestProject=true`, `IsPackable=false`, versions from central package management, `net10.0`.
- Helper libraries (`Cosmos.Tests.Infrastructure`, `Cosmos.Quotations.Testing`, `Cosmos.Sql.Hedgehog`, `Cosmos.Quotations.Tests.Models.Hedgehog`, the adapter `Hedgehog.MSTest`; the test model `Cosmos.Quotations.Tests.Models` needs no test framework at all) reference `MSTest.TestFramework` only, not the `MSTest` metapackage, so they are never runnable test applications. One test executable is never referenced from another.
- Test executables with Hedgehog properties (`Cosmos.Sql.Tests`, `Cosmos.Quotations.Tests`, the adapter's suite) reference `Hedgehog.MSTest`. MSTest 4 discovers only non-static methods returning exactly `void`, `Task` or `ValueTask` *(verified)*: one `[<Property>]` returning `bool`, `Task<unit>`, `Task<bool>` or `Property<unit>`, or one static `[<Property>]`, makes discovery of the **whole** assembly fail with UTA007 *(verified)*, because `TreatDiscoveryWarningsAsErrors` defaults to true (`MSTestSettings.cs:54`, read in the source), and the F# build gives no warning *(verified)*; `Result` and `Async` returns fail the same return-type check (`MethodInfoExtensions.cs:92-96`, read in the source, not run). The test application then ends with an unhandled `AggregateException`, exit code -532462766 (0xE0434352), which a shell keeping eight bits shows as 82 – not a Microsoft.Testing.Platform exit code *(verified with the executable and with `dotnet test`)*. Generic test methods pass discovery although the `TestMethodAttribute` XML docs require non-generic ones (§22.6). CI therefore runs `--list-tests` on every test executable before the test run.
- Every test project ships `testconfig.json` with method-level parallelism and `workers: 0`, copied to the output directory. Classes that share mutable state opt out with `[<DoNotParallelize>]`.
- When a category filter is applied across several test projects, the run passes `--ignore-exit-code 8`, otherwise a project with zero matching tests fails the lane.

### 22.2 Base classes and categories

- `TestBase` owns `TestContext` and exposes `CancellationToken` from `TestContext.CancellationTokenSource.Token`.
- The emulator base carries the category `"Cosmos DB Emulator"` through a `TestCategoryBaseAttribute` subclass (the maintainer's standard filter string), so every derived class inherits it. Finer categories of §13 are added next to it.
- **Translation and golden tests stay off the emulator base class**, so they run on Windows and macOS jobs without an emulator. In the application even pure translation tests inherit the emulator base, which excludes them from emulator-free lanes.
- Two database lifetimes. *Per test* (write tests): created in `[<TestInitialize>]`, deleted in `[<TestCleanup>]`; never the home of a `[<Property>]` method, because MSTest runs the constructor, `[<TestInitialize>]` and `[<TestCleanup>]` for every generated case and every shrink step (§22.6); property tests only read class-scoped datasets, and round trips stay hand-written slim/fat tests with per-test databases (maintainer decision 2026-09-28, §2). *Per class* (read-only conformance suites): a generic `ReadOnlyIntegrationTestBase<'Factory>` with `[<ClassInitialize(InheritanceBehavior.BeforeEachDerivedClass)>]`/`[<ClassCleanup>]`, fixtures stored in a `ConcurrentDictionary` keyed by `FullyQualifiedTestClassName`, the factory created through a static abstract `Create` member. A single static slot on a generic base is shared by every class deriving from the same closed generic type; the application documents that defect.
- The library test projects do not use Microsoft.Extensions.Hosting or DI: there is no application to host. The equivalent extension points are abstract members of the emulator factory (serializer options, container definitions, plugins).
- The infrastructure's base factory is `DatabaseTestFactory`, created through the static abstract `Create` of `IDatabaseTestFactory<'Factory>` *(names proposed)*, the counterparts of the application's database test factory and its generic factory interface *(verified)*. It replaces the repository's own `DatabaseTestApplicationFactory` (`tests/Cosmos.Tests.Infrastructure/IntegrationInfrastructure.fs:47`, moved there by #39), which the per-test base creates through the abstract instance member `CreateApplication` and whose `SeedDataAsync` takes the cancellation token as a parameter (`:200-201`) *(verified)*. Its abstract members are the extension points above and `SeedDataAsync ()`, which does nothing unless a scenario overrides it (the application's `abstract member SeedDataAsync : unit -> Task` with `default _.SeedDataAsync () = Task.CompletedTask`) and takes the token from the factory's `TestContext`, as the application's scenarios do (§22.4). The two lifetimes above create it in `[<TestInitialize>]` and in `[<ClassInitialize>]`, as the application's per-test and read-only integration test bases do *(verified)*. Scenario factories derive from it, implement `Create` and live next to their tests (§22.6).
- A logical suite is split over several files by an abstract base holding shared data plus one concrete `[<TestClass>]` per file, named `<Suite>Tests.<Aspect>.fs`. Test methods, `[<Property>]` ones included, belong to the concrete classes: MSTest 4.2.3 runs a test method declared in the abstract base once per derived `[<TestClass>]` *(verified with an inherited `[<Property>]` and two derived classes)*, which only the per-layout-variant classes of §13 rung 6 want.
- Parallel scope follows the fixture lifetime: `method` for projects whose class fixtures are read-only after initialisation, `class` when a class fixture is mutated (the application's host-based integration project uses `class`).
- MSTest allows one `[<AssemblyInitialize>]` per assembly, so the capability probe and the sweep of leftover databases share one method.
- Category attribute classes replace string constants, as `tests/Cosmos.Tests/TestCategories.fs` already states; the application keeps separate constants and that habit is not copied.
- Test projects reference the infrastructure project through `tests/Directory.Build.props`, with a condition that excludes the helper projects themselves, the test model `Cosmos.Quotations.Tests.Models`, which needs no test framework (§22.1), and the two adapter projects `Hedgehog.MSTest` and `Hedgehog.MSTest.Tests`, which stay free of the Cosmos infrastructure because they are also proposed upstream (§5).

### 22.3 Database identifier

The application's algorithm replaces the repository's current one: the test name is read from `TestContext.Properties["TestName"]` and falls back to `FullyQualifiedTestClassName` in class-level contexts (where reading `TestName` throws); invalid characters are replaced by `_`; the name is truncated to 80 characters; data-driven tests get a hash suffix. Corrections to the application's version:

- sanitise against an explicit set that includes the characters Cosmos forbids in ids (`/`, `\`, `?`, `#`), because `Path.GetInvalidFileNameChars` differs per platform and does not contain `#`;
- include a short hash of the class name, because two classes with an equally named method collide;
- compute the data-row hash with a stable hash function, because `String.GetHashCode` is randomised per process and leftovers of an aborted run are then never reused or swept;
- add a common prefix so an `[<AssemblyCleanup>]` sweep can delete leftovers by name (the application gets its prefix from the configured database name, to which the identifier is appended); the prefix is `fsac-test-`, and the name alone never marks a database as a leftover, because a concurrent run on the same emulator uses the same prefix: the sweep also requires an age (§22.4);
- truncation must keep the distinguishing part: with a prefix in front, the method name sits at the end, so the name is shortened in the middle or a stable hash of the full name is appended.

### 22.4 Emulator budget, creation and cleanup

- A process-wide semaphore guards the emulator's partition budget; a test acquires one permit per container it creates. The limit comes from the environment variable `COSMOS_EMULATOR_PARTITION_COUNT` (default 25, the Windows emulator's default): the application hard-codes 250 while its pipeline starts the emulator with `-PartitionCount 50`. On the Windows emulator one container costs one partition and a database costs none *(verified in Phase 0)*: the emulator refused the 20th container with 503, sub-status 1007, whether the containers sat in 1, 3 or 40 databases. What a container costs on the vNext emulator is still a probe.
- An emulator may hold fewer containers than the default budget: one Windows emulator held 19 *(verified)*. The existing suite still passes there at 32 workers, because creation is serialised (below); machines with a smaller emulator set `COSMOS_EMULATOR_PARTITION_COUNT` (whether the default should drop below 25 is open, §18 item 14).
- The budget and the leftover sweep are per process: two test runs on one emulator share its partitions but not the semaphore. The sweep runs at assembly start and end and deletes only databases with the `fsac-test-` prefix (§22.3) that stayed unmodified for at least an hour (`COSMOS_TEST_LEFTOVER_AGE_MINUTES`), so concurrent runs on one emulator do not delete each other's live databases.
- Permits of one test are acquired **atomically**: acquiring them one at a time can deadlock when several tests each hold part of their permits. The fixture records how many permits it really took and releases exactly that number; the application releases unconditionally, which over-releases the semaphore when initialisation fails early.
- Database and container creation is serialised across parallel tests by a second semaphore, with the wait placed before the `try` so a failed wait cannot release a permit it never took.
- Cleanup is best-effort: a failed deletion is written to `TestContext` and never fails the test; permits are released in `finally`; cleanup tolerates a partially initialised fixture.
- Setup, seeding and cleanup pass the cancellation token, so a hung emulator does not block until the request timeout.
- Databases are created without throughput, as the repository does today.

### 22.5 Containers, client and serializer

- Container definitions are data: `ContainerDefinition = { Name; PartitionKeyPaths; UniqueKeys; ComputedProperties; CompositeIndexes; IncludedPaths; DefaultTtl; Udfs; VectorPolicy; FullTextPolicy }` and one creation routine. Test datasets include a container with a two-level hierarchical partition key and a polymorphic class hierarchy with `JsonDerivedType` discriminators, mirroring the application.
- The client keeps the repository's settings (Gateway mode, HTTP client restricted to local hosts), which the Linux vNext emulator needs; endpoint and key are read from `COSMOS_EMULATOR_ENDPOINT` and `COSMOS_EMULATOR_KEY` when set, so the same tests run against the Windows emulator lane. That lane is nightly and non-blocking from Phase 0, because the features the application queries (UDFs, computed properties, composite indexes) are absent or no-ops on the vNext emulator. The application's tests run only on the Windows desktop emulator; the library's default lane is the Linux vNext emulator.
- The serializer of the conformance suites is STJ + FSharp.SystemTextJson. The layout matrix contains the library defaults, the maintainer production profile (§21.3) and the variants of §13; for the tuple assertions the layout conformance rung adds the plain-STJ layout (`JsonLayout.systemTextJson`) with `IncludeFields` off and on. One probe client is built with a custom `CosmosLinqSerializer` that implements `IJsonSerializerOptionsProvider`.
- **Layout conformance rung** (new in §13): for each supported variant, slim and fat instances of the target types (`<type>SlimGen`/`<type>FatGen` of §22.6, drawn with the seeded `Sample` members) are serialised with the real serializer, parsed to `JsonNode`, and every path and encoding the `IJsonLayout` reports is asserted against the produced JSON. The application's serialization tests assert only deserialisation, run with options that differ from the Cosmos client's, and therefore do not pin the stored layout. The rung also pins the absence encodings the test model relies on *(verified with FSharp.SystemTextJson 1.4.36)*: on a **class** property `Skip` is written as `null` – with plain `JsonFSharpConverter ()`, with `DefaultIgnoreCondition = WhenWritingNull` and with `JsonFSharpOptions.Default ().ToJsonSerializerOptions ()` – and so is `ValueNone` under the plain converter; a `Skippable<'T>` property is omitted only when it carries `[<JsonIgnore(Condition = JsonIgnoreCondition.WhenWritingDefault)>]`, while `WhenWritingNull` on it throws `InvalidOperationException` because `Skippable` is a struct; a **record** field holding `Skip` is omitted without any attribute. The model has skippable members in both forms (§22.6), so the rung fixes per member whether a skipped value is missing (`IS_DEFINED` false) or `null` in the stored document. Tuples are asserted for both kinds at arities 2, 3 and 8: `[1,"a"]` under FSharp.SystemTextJson, the production profile included; for the plain-STJ layout `{"Item1":…}` for reference tuples and `{}` for struct tuples with `IncludeFields` off, `{"Item1":…}` for both with it on; a struct-tuple projection that the layout reports as not serialised must be refused, never round-trip to default values.

**Sampling and determinism**

- `Sample.single`/`Sample.multiple` keep the application's semantics – random size 1–100, `Gen.sample`'s random seed, nothing logged *(verified)* – for hand-written emulator tests and scenarios whose data need not be replayed; `multiple` is kept although the application never calls it, the equally unused `largeSingle`/`largeMultiple` are dropped. Added, in neither the conventions nor the application: the seeded `singleWith seed size` and `multipleWith seed count` (sketch below), where value i gets the seed `seed + i` and the size `1 + i % 100`, so determinism does not bring back the fixed small size that collapses ranges and duplicates ids *(verified deterministic)*; `Gen.sampleFrom` also draws a random seed *(verified)*. Differential suites, shared datasets and data-driven rows use only the seeded members, with one `[<Literal>]` seed per suite in a `Seeds` module (`Seeds.Differential = 2026UL`), written to `TestContext` at class initialisation and passed by properties to the adapter's `Seed` setting (Property execution); for shared datasets this replaces the `Sample.single` of the seeding conventions, because they must be replayable.
- Every seeded draw of one dataset has its own seed (`multipleWith seed n` occupies `seed` to `seed + n - 1`): the same seed repeats the same `Gen.guid` ids in structurally equal generators, even with different pins and sizes *(verified)*.
- Raw `Gen.sample` appears neither in tests (the application calls `Gen.sample 1 n`, size 1, in four scenario factories *(verified)*) nor inside a generator. `DynamicData` rows are constants or come from the seeded members: a static member that samples with `Sample.single` is evaluated again on each access, so discovery and execution see different data *(verified)*.
- Uniqueness is by construction: ids and keys come from `Gen.guid`, which follows the seed *(verified)*, or derive from the element index and are pinned through the config; sets collapse duplicates, so size assertions use the generated set's `Count`. Inside a property this does not isolate invocations: `Gen.guid` shrinks byte-wise towards `Guid.Empty`, so shrink candidates repeat ids and a counterexample's id is `00000000-0000-0000-0000-000000000000` *(verified: a failing seed-42 property of 124 invocations saw 80 distinct ids; a greedy shrink walk at seed 2026, size 50, took 18 invocations, one of which reused an id already written)*; property tests never write (maintainer decision 2026-09-28), so repeated ids cannot collide in a container; they matter only to assertions that expect distinct ids. `Gen.distinct`/`Gen.distinctBy`, which the generator conventions recommend, are not adopted: the application's implementations call `Gen.sample` inside `Gen.sized`, returned different values under the same property seed and never shrink *(verified)*; the only verified pure replacement needs `Gen.filter`.
- No Bogus, so the rule of the generator conventions for the shared Bogus faker has no counterpart (the application's faker is seeded from `Random.Shared`, outside the Hedgehog seed *(verified)*) and no clock (its `DateOnlyGen.past`/`future` read `DateTime.Today` on every sample *(verified)*). Text comes from `Gen.alphaNum`/`Gen.string`/`Gen.item` (`TextGen.nameString` and `notes` are copied; `capitalize` uses `Char.ToUpperInvariant` where the application calls the culture-sensitive `ToUpper ()`; the Bogus-based `lorem*` have no counterpart), dates from fixed bounds around one reference-date constant (`DateOnlyGen.between` over `DayNumber`). Foq, BlackFox.MasterOfFoo, Bogus and Microsoft.Extensions.Hosting, used by the application's tests, are not needed.

The seeded `Sample` members (the sketches of this section are cut from code compiled and run with `dotnet fsi --langversion:10.0 --checknulls+ --warnon:3390` against Hedgehog 2.0.4, FSharp.SystemTextJson 1.4.36, MSTest.TestFramework 4.2.3 and FSharp.Azure.Cosmos 1.0.1 *(verified)*):

```fsharp
/// Samples one value at the given seed and size; the same pair always gives the same value.
let singleWith (seed : Seed) (size : int) (source : Gen<'a>) : 'a =
    source |> Gen.toRandom |> Random.run seed size |> Tree.outcome

/// Samples count values; value i uses the seed seed + i and the size 1 + i % 100, so the values cover all sizes.
let multipleWith (seed : uint64) (count : int) (source : Gen<'a>) : 'a array =
    Array.init count (fun i -> singleWith (Seed.from (seed + uint64 i)) (1 + i % 100) source)
```

**GenConfig records**

- Every test type with optional members has a `<Type>GenConfig`: one `Gen<'T>` field per member, `'T` copying the member type (`option`, `voption` and `Skippable` stay as they are); `static let slim` listing every field; `static let fat = { slim with … }` and `static let defaultValues = { slim with … }` changing only the optional and collection fields, repeating no unchanged one (`static let default` does not compile, FS0010, `default` being a keyword *(verified)*, hence the name `defaultValues` from the generator conventions); `static member Slim`/`Fat`/`Default`; `member config.CreateGen () : Gen<'T>` with one `let!` per field in field order (a derived config binds its own fields, then calls the nested base) that builds a class with the required values as constructor arguments and the optional ones as named initialisers, never by assignment after construction. Types without optional members – scalar wrappers, unions used as ids, fieldless unions, nested records without optionals – keep a plain leaf generator without Slim/Fat/Default.
- **Slim** (maintainer 2026-09-28: all optionals empty): required values only; optionals `Gen.constant ValueNone`/`None`/`Skip`; collections empty (`Gen.constant ImmutableArray<_>.Empty`, `Set.empty`, `Map.empty`, `[]`); optional members of a non-option type at the member default (`""`, `0`). **Fat** (maintainer 2026-09-28: all optionals filled, no empty value at all): optionals `leafGen |> Gen.map ValueSome` (`Some`, `Include`; no application config has a `Skippable` field *(verified)*, so `Skip`/`Include` extend the `voption` form); optional members of a non-option type get a value other than the member default from a leaf generator whose range excludes it (text of length 1 or more, a non-zero number), and text inside `ValueSome`/`Some`/`Include` is non-empty too, because the maintainer's Fat has no empty value *(the plan's reading of "no empty"; Default gives such members the default or another value with equal probability)*; collections non-empty through a bare `Gen.list (Range.linear 1 3)` or a range-taking helper such as `CollectionGen.immutableSortedSet (Range.linear 1 3)` (the application's `CollectionGen.sortedSet (Range.linear 1 3)`), never a 0-bounded `CollectionGen` helper: `Range.linear 0 5` gives an empty collection in about 45 % of `Sample.single` draws *(verified)*, which leaves several of the application's Fat collections possibly empty. Collections of unrestricted size in leaf generators pass the element generator straight to a `CollectionGen` function instead of `Gen.list (Range.linear …) |> Gen.map …`; a collection type it does not cover gets a new function there.
- **Default** (maintainer 2026-09-28: total random): every optional member independently present or absent, every collection independently empty or not, every value from its leaf generator's full range. This supersedes the older pair of the generator conventions – `Default` for bounded values pinned to a constant, `Random` for full ranges, both added only when a field is pinned – so there is no `Random` variant, and a constant pin goes into one record update of `Slim`, `Fat` or `Default` at the call site or into a named variant (next bullet); no application config has `Default` or `Random` *(verified)*. The bounds the translator needs (fixed date bounds, integers within ±2^53, decimal precision, document size) are ranges of the leaf generators and of `CollectionGen`, and Default uses them in full.
- A named variant several tests reuse is `static let <name> = { <variant> with … }` with a documented `static member <Name>` next to `Slim`/`Fat`/`Default` and a documented top-level generator (the application has exactly one: a role configuration's permissions variant with its matching top-level generator); a variant one test uses stays a config at its call site.
- **How Default keeps absence and emptiness common** *(the plan's choice)*. `static let defaultValues = { slim with … }` fills every optional field with a balanced helper, `Gen.voptionBalanced`/`Gen.skippableBalanced`/`Gen.optionBalanced` (`Gen.frequency [ 1, Gen.constant ValueNone; 1, Gen.map ValueSome source ]` per carrier: absent with probability about 0.5 at every size, shrinking first to the absent case *(verified for all three)*), every collection with the balanced emptiness twin of its `CollectionGen` function, `CollectionGen.<name>Balanced` (empty or `Range.linear 1 n` with equal weight: empty in 50 % of draws at every size *(verified over sizes 1–100)*), every owned child with the child config's `Default` and a nested base with `<Base>GenConfig.Default`. Top-level names follow the pattern of the conventions' `<type>SlimGen`/`<type>FatGen`: `<type>DefaultGen`, and `get<Type>DefaultGen <pinned values>` only when several tests pin the same values; the conventions' `default<Type>Gen` named the superseded pinned variant. Sized helpers would make absence and emptiness rare: the conventions' "Optionals: `Gen.voption`, `Gen.skippable`" (`Gen.sized (fun n -> Gen.frequency [ 2, Gen.constant ValueNone; 1 + n, Gen.map ValueSome source ])`) and Hedgehog's `Gen.option` are absent with probability 2/(3+size), in about 7 of 100 tests over sizes 1–99 (6.2 % measured: 18 % at size ≤ 20, 2.9 % above 50), and a 0-bounded range ties emptiness to size (`Range.linear 0 5`: 97 % empty at size ≤ 20, 25 % above 50) *(verified)* – too few absent values to exercise null-versus-undefined translation beyond small sizes. The sized helpers are ported verbatim for parity; the application's configs do not use them either (Slim and Fat are constant, `Gen.voption` has one caller, at a call site *(verified)*). The balanced helpers keep their rates when a property pins `Size` (Property execution). Hedgehog's auto-generation is no substitute: `Gen.auto` draws a `voption` case uniformly but an `option` through the sized `Gen.option`, and list emptiness depends on size *(verified)*.
- **Base class configs.** `<Base>GenConfig` holds every member of the abstract base; its `CreateGen<'T when 'T :> <Base>> (create : <constructor values> -> 'T)` generates the base values, calls `create` and assigns the settable base properties through the upcast – the one assignment the pattern cannot avoid. A derived config nests it in a field named after the base (`Document`, as the application names such fields after their bases), takes its `Slim`/`Fat`/`Default` in the matching variant, binds its own values first and passes them through the class initialiser inside `create`, as the application's derived configs do. The generator conventions' own base-class example and the application config it is taken from assign after construction; not copying them is an adaptation to the repository's class-initialiser rule. Base values are pinned by nested updates (`{ config with Document.TenantId = … }`); a base config whose derived class adds nothing exposes `Create<Derived>Gen ()`, as the application does; each schema version of a discriminated type is its own derived class with its own config (§21.1). A polymorphic dataset draws from `any<Base>Gen`, a `Gen.choice` over every `JsonDerivedType` registration upcast to the base, in each variant; the application's counterpart uses Slim only and omits one unregistered type.

- Records are returned as `({ … } : <Type>)`, because their labels equal the config labels. A `[<Struct>]` record and its reference twin share one config through a second method (`CreateGen ()`/`CreateStructGen ()`), as one of the application's configs does for a record and its input twin, so "struct translates exactly like reference" (§20.11) runs on identical values. - Values the document computes or the server assigns – `_ts`, `_etag`, the `$type` discriminator written from `JsonDerivedType`, computed properties, keys derived from other members – are not config fields. A composed id keeps its parts as fields and combines them in `CreateGen`. A member the type defaults without an option type (the §21.2 wrapper over a nullable backing field, `MemberDefaults`) gets a `Gen<'T voption>` field, documented as assigned only on `ValueSome`, so Slim leaves the stored member absent and exercises `(IS_DEFINED(p) ? p : @default)`; Fat always assigns it and Default assigns it with probability 0.5. Members the translator supports only in a later phase, or the vNext emulator cannot store, are left out of the test model until that phase instead of staying empty in Fat, which the maintainer's Fat definition rules out *(the plan's choice; the generator conventions keep such values empty in Fat; open in §18 item 12)*.

- Every generator `let`, private ones included, and every `static let` has a `///` doc comment, as the generator conventions require; every config type, static member, `CreateGen…`, `For…` and `CreateGenFor…` method is documented too (the repository's rule), plain or explicit XML; the application's undocumented config types and its two plain comments that carry `<see cref>` are not copied.

**Call sites**

- A test that needs fields pinned builds one record update from `Slim`, `Fat` or `Default` and calls `CreateGen ()`: it never mutates a sampled document, copies it with `{ x with … }` or rebuilds one from a sampled one, never chains single-field methods and never combines an update with `CreateGenFor…` (those values go into the same update). **Generator facts the translator tests depend on** *(verified)*

- `Gen.dateTimeOffset` yields arbitrary offsets such as `-06:49`, whose ISO strings do not sort in instant order: date leaf generators map to UTC (`Gen.map _.ToUniversalTime()`).
- `Gen.decimal` yields up to 15 significant digits – up to 11 fractional digits from 1 000 upwards, up to 15 below 1 – and Cosmos DB stores numbers as doubles: decimal leaf generators round to the precision the member declares (the sample: two places over 0–10 000, `Math.Round (d, 2)`).
- The model holds `Skippable` members in both forms that §22.5 distinguishes (a skipped value written as `null` or omitted), and the layout rung pins which is which.
- A single-case union with a private case serialises unwrapped with the default `JsonFSharpConverter` and round-trips, over `string`, `Guid`, `int`, `DateTimeOffset` and `DateOnly` alike, generic phantom-typed wrappers included *(verified with FSharp.SystemTextJson 1.4.36)*.

**Hedgehog MSTest adapter** (`tests/Hedgehog.MSTest`, §5; delivered in Phase 0, §16; prototypes were built, the extended one also run on MSTest 4.3.2)

- **Mechanism** *(verified)*. `PropertyAttribute` inherits `TestMethodAttribute`, forwards `[<CallerFilePath>]`/`[<CallerLineNumber>]` optional parameters to the base constructor as `STATestMethodAttribute` does (F# fills them for attribute constructors, upstream's six constructor overloads included), and overrides `ExecuteAsync (testMethod : ITestMethod) : Task<TestResult[]>`, which MSTest calls instead of its own single invocation. Hedgehog generates the arguments, each case is one `testMethod.InvokeAsync arguments` – never `MethodInfo.Invoke`, which the MSTest docs rule out – and the run folds into one `TestResult`. A test method with parameters and no data source is accepted at discovery. MSTest has no counterpart to xUnit's discoverer, test case and runner chain or to NUnit's `ISimpleTestBuilder`/`IWrapTestMethod`, so the framework layer is this one attribute.
- **Parity** with `Hedgehog.NUnit` 1.0.0 and `Hedgehog.Xunit.v3` 2.0.0 *(upstream behaviour verified by building and running its suites)*: `[<Property>]` with upstream's constructor overloads `()`, `(tests)`, `(tests, shrinks)`, `(autoGenConfig)`, `(autoGenConfig, tests)`, `(autoGenConfig, tests, shrinks)` and the named settings `AutoGenConfig : Type`, `AutoGenConfigArgs : obj[]`, `Tests : int<tests>`, `Shrinks : int<shrinks>`, `Size : Size`; class-level `[<Properties>]` with the same settings; `[<Recheck>]`; abstract `GenAttribute<'T>` and upstream's 18 built-in parameter attributes (`Int`, `Odd`, `Even`, `PositiveInt`, `NonNegativeInt`, `NonZeroInt`, `Identifier`, `LatinName`, `SnakeCase`, `KebabCase`, `DomainName`, `Email`, `DateTime`, `DateTimeOffset`, `AlphaNumString`, `UnicodeString`, `Ipv4Address`, `Ipv6Address`); `AutoGenConfig` types with exactly one public static member returning `IAutoGenConfig`, optionally taking `AutoGenConfigArgs`, and a clear error otherwise; every other parameter from `Gen.autoWith` with the merged configuration; parameters journalled by name in Hedgehog's `Journal`; `IDisposable` arguments disposed after each invocation; precedence `GenAttribute` > `[<Property>]` > `[<Properties>]` > `AutoGenConfig.defaults`; a run that gives up after Hedgehog's fixed 100 discards fails (NUnit sets `Failure`, xUnit raises through `Report.tryRaise`; the prototype reported it as inconclusive, which the runner shows as skipped).
- **Additions beyond upstream** *(the plan's choice)*: `Seed`, a `uint64` fed from a `[<Literal>]` such as `Seeds.Differential` *(verified)*; data rows – MSTest unfolds each `[<DataRow>]`/`[<DynamicData>]` row into its own test and passes it as `ITestMethod.Arguments`, a `TestDataRow<struct (…)>` unpacked into its items, which the adapter keeps as the leading arguments while generating the rest *(verified for `DataRow`, `DynamicData` and `TestDataRow<struct (string * int)>`)*; `Assert.Inconclusive` in an invocation is a Hedgehog discard, and a failure while rechecking *(both verified)*. One result per property or row, because several results from one `ExecuteAsync` appear as separate results under one test id and inflate the totals *(verified)*.
- **Deliberate departures from upstream** *(the plan's choice; upstream behaviour measured)*: class-level settings come from the test class MSTest runs, `testMethod.MethodInfo.ReflectedType`, not from `DeclaringType` as in both upstream adapters and the prototype – MSTest runs a property inherited from an abstract suite base once per derived `[<TestClass>]`, whose type is the reflected one while the declaring type is the base, so the prototype ignored a derived class's `[<Properties(Tests = 4, AutoGenConfig = …)>]` and ran 100 auto-generated cases *(verified)*; along the class chain a derived class's `[<Properties>]` wins over its base's (upstream: the base wins); a `GenAttribute` is found through the whole inheritance chain via a non-generic base attribute (upstream checks only the direct base type and silently auto-generates for an attribute derived from a built-in one); generic property methods, which MSTest 4.2.3 discovers and upstream closes over `obj`, get a failed result naming the rule before any generator is built; `TargetInvocationException` is unwrapped; each shrink-tree node's invocation is memoised in a lazy task, because Hedgehog 2.0.4 re-runs an asynchronous test case whenever it is unwrapped and reads the final counterexample's `Journal` from a second invocation – a doubled database side effect and a report that can contradict the failure *(verified)*; `Property.reportTaskWith` runs without blocking, `Property.reportRecheckWith`, synchronous in 2.0.4 and ignoring its configuration argument, runs on `Task.Run`; any exception, generator construction included, becomes an `Error` result instead of escaping `ExecuteAsync` (the prototype built generators outside its `try`, so a generic property method surfaced as an unhandled exception of the attribute *(verified)*).
- **Code.** Upstream's nine framework-neutral files under the namespace `Hedgehog.MSTest` (§14), plus `PropertyAttribute`, `PropertiesAttribute` and an invoker entry point in `InternalLogic` (a function from arguments to `Task<TestResult>`, so the suite can drive the runner without MSTest), in upstream's file layout. Upstream's return-value wrapping (`bool`, `Property<_>`, `Result`, `Async`, `Task<T>`) is dropped: MSTest awaits `Task` and `ValueTask` itself, and the other return types never pass discovery (§22.1). The repository's rules apply to the port – `voption`, struct tuples, XML docs, Fantomas, no `.AsTask ()` (upstream converts `ValueTask` that way), no nullness warnings (the nine upstream files give 23 under the repository's `Nullable=enable` *(verified)*) – and every copied file keeps its Apache-2.0 attribution *(style open in §18 item 12)*. `InternalsVisibleTo` exposes the runner to `Hedgehog.MSTest.Tests` only.
- **Suite** (`tests/Hedgehog.MSTest.Tests`): upstream's F# xUnit tests (126, covering recheck, size, shrinks, `AutoGenConfigArgs`, `IDisposable` arguments) and NUnit tests (52) rewritten as `[<TestClass>]` types, without the return-value cases MSTest cannot discover; tests for every addition and departure above; failing properties asserted through the invoker entry point instead of failing the suite; at least one plain `[<TestMethod>]`. The `PropertyTests.fs` of the earlier MSTest rename of the old `hedgehogqa/fsharp-hedgehog-xunit` repository (783 lines) serves as a checklist (§14).

**Scenarios and seeding** (the seeding conventions)

- A scenario lives next to its tests in `tests/Cosmos.Quotations.Tests/Scenarios/<Scenario>.fs`, registered in the fsproj before the test files that use it, not in `Cosmos.Tests.Infrastructure`: that project is shared with `tests/Cosmos.Tests`, which must not depend on the Quotations test model, so it keeps only the base factory and the fixtures (§22.2). Each scenario file declares its own namespace `FSharp.Azure.Cosmos.Quotations.Tests.<Scenario>` (the application likewise gives each scenario its own namespace), so every scenario names its types `TestData` and `TestDatabaseFactory` (the seeding conventions name the factory after the application host). A factory that already seeds what a test needs is extended, not duplicated. The canonical scenario of the seeding conventions mutates a generated document and calls `Gen.distinct`; neither is copied.
- Shape: a `[<Struct>] TestData` record and a factory that derives from the base factory, generates everything in its constructor (`let` bindings) and exposes `member val TestData : TestData = { … }`. `override this.SeedDataAsync () : Task` only persists what the constructor generated, never samples, through the library's own operations (`container.ExecuteAsync (create { item x; partitionKey pk }, cancellationToken)`, the key from the container's partition-key builder as the seeding conventions require for every item, the token from the factory's `TestContext`), and asserts `CosmosAssert.IsOk` on every response – stricter than the seeding conventions, whose sample discards the responses – so seeding uses the same serializer as the translator's parameters; heterogeneous documents (missing properties, wrong types) are written as streams. The factory implements the base's static abstract `Create` – `interface IDatabaseTestFactory<TestDatabaseFactory> with static member Create (ctx : TestContext) = new TestDatabaseFactory (ctx)` with `/// <inheritdoc />`, the counterpart of the factory-interface implementation in the seeding conventions, generic in the application's code (§22.2) – through which the fixtures of §22.2 create it.
- `TestData` exposes only what tests read. Documents that exist only to be excluded by a predicate stay private `let`s; no field implies a document the factory does not seed, and a value deliberately not seeded is named so (`MissingId`). Filter anchors are `Known<Member>` fields pinned in the factory with one config update, so every golden predicate has a guaranteed match; `Other<KeyMember>` values cover cross-partition cases. Field names match the variant they hold (one of the application's fields named for Slim holds a Fat sample *(verified)*). Example *(verified: compiled with stubs for the base factory and the partition-key builder)*: a persons scenario draws `tenantId` with `Sample.singleWith (Seed.from Seeds.Persons) 50 tenantIdGen`, the `KnownNick` anchor document from `{ PersonDocumentGenConfig.Fat with Document.TenantId = Gen.constant tenantId; Nick = Gen.constant (ValueSome knownNick) }` at the seed `Seeds.Persons + 1UL`, the other persons with `Sample.multipleWith (Seeds.Persons + 2UL) 50 (getPersonDocumentSlimGen tenantId)`, and seeds `[| nickedPerson; yield! otherPersons |]`.
- Test methods deconstruct only the fields they use – `let { KnownNick = knownNick; NickedPerson = nickedPerson } = this.TestData`, never `let td = this.TestData` – and never sample documents of the dataset; they may sample documents they write themselves (create, replace, upsert and patch tests; the mutation inputs of the seeding conventions) and captured query arguments (the library's addition).
- Lifecycle (§22.2): write tests create the factory per test, so their data is generated per test; read-only suites create it once per class, keyed by the class name, so the shared dataset is generated and seeded once.

### 22.7 Assertions and style

- Assertion helpers are sealed static classes marked `DebuggerNonUserCode` with paired members: `Want*` returns the unwrapped value or fails, `Is*` discards it, the optional message comes last. `CosmosAssert` and `Assert` move to the shared infrastructure; a `TranslationAssert` is added in the same style (`WantOk`, `WantError`, `WantErrorCode`, `SqlEquals`). Defects of the application's helpers are fixed on the way (`WantConflict` returns the function `ignore`; several helpers fail with a null message).
- Whole-entity comparison uses CompareNETObjects through one shared `EntityCompareLogic` with custom comparers for option, voption, Skippable, sets, collections and `JsonElement`. It is used for projected class instances and whole documents; id sets and scalar values are compared with structural equality, JSON shapes with `JsonNode.DeepEquals`. The package is test-only and accepted (maintainer decision 2026-09-27, §18 item 11): CompareNETObjects 4.84.0, the application's version, licensed Ms-PL, referenced only by `Cosmos.Tests.Infrastructure`; it brings `System.Configuration.ConfigurationManager` 8.0.0 and `System.Drawing.Common` 8.0.0 transitively and sets `requireLicenseAcceptance` *(verified in the 4.84.0 nuspec)*. The repository's written rules win over the application's habits: no file-wide `#nowarn`, Unquote for complex facts only, a message on every `Assert.*` call.
- Server-assigned metadata never enters a whole-document comparison, and generated values stay untouched (maintainer answer 2026-09-28, §18 item 12): `EntityCompareLogic` lists the members mapped to `_etag` and `_ts` in `ComparisonConfig.MembersToIgnore` *(API verified in CompareNETObjects 4.84.0)*, and a custom extension-data comparer, to be written with the others, skips underscore-prefixed keys. This departs from the application, which copies the response's ETag onto the generated entity before `CompareLogic.Assert` (57 assignments in 9 files *(verified)*). The generator conventions do not address that idiom; the library does not copy it because on the records of the differential suites (§22.6) it would need the `{ x with … }` copy of a generated record that the conventions' rule on overriding fields rules out. A test whose subject is the ETag (optimistic concurrency) asserts it explicitly.
- **Exact assertions.** Counts and lists are asserted exactly; the application's lower-bound and upper-bound assertions would pass for a wrong query. Translation assertions are full SQL plus parameter baselines, or result sets.
- Test names are double-backtick sentences of the form `<construct or member> must <expected SQL or result> when <condition>`. Asynchronous tests are declared `) : Task = task {`; IcedTasks expressions are for library code, not test bodies.
- Data-driven cases use `[<DynamicData>]` over a static member whose rows carry a readable case name, so each case is a separate test result and failures print names. Rows are constants or come from the seeded `Sample` members, never from `Sample.single` (§22.6). The one exception to `[<DynamicData>]` is the slim/fat pair of a hand-written emulator test: two constant `DataRow`s with `DisplayName` (§22.6); a `[<Property>]` chooses its variant through its generators and takes rows – `DataRow` constants or `DynamicData`/`TestDataRow` rows from constants or seeded members – only ahead of its generated parameters (§22.6; all three row forms ran with the adapter prototype *(verified)*). Typed rows are `TestDataRow<struct (…)>` with `DisplayName`, never reference-tuple rows: the MSTest 4.2.3 XML docs allow a `Tuple` or a `ValueTuple` value for methods with several parameters; MSTest 4.2.3 unpacks a `TestDataRow<struct (string * int)>` row into two parameters at run time and keeps its `DisplayName` *(verified through the Hedgehog adapter prototype, whose `ITestMethod.Arguments` held the two items ahead of a generated third parameter)*; a plain `[<TestMethod>]` and larger arities are checked in Phase 0. Each truth-table case lists accepted and rejected inputs.
- Failure messages state what was expected and include the rendered quotation fragment and the error code.
- Unsupported programs are asserted with `Assert.Throws<CosmosQueryTranslationException>` followed by a check of the error code; for `QueryAsync` the sequence is enumerated inside the lambda.
- Every execution member has one test that cancels the token and asserts `OperationCanceledException`.
- Predicate combinators are tested for three properties, as the application does for its predicate combinators: the result parameter type, the absence of untranslatable nodes after combination, and semantic equivalence by evaluating the combined predicate on sample values.
